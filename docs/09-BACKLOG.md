## 1-2. ★ UI 다듬기 (Phase 7)

> ★ 분류 기준은 [07-DECISIONS.md](07-DECISIONS.md) D-031 이다.
> **정보가 도달하고 조작도 되지만 세련되지 않은 것**만 여기 온다.
> 정보가 도달하지 않거나 조작을 막거나 기능을 오해하게 만드는 것은 **그 라운드에 고친다.**
>
> ★ 지적을 받으면 그 자리에서 분류해 여기 적는다. 기억에 두지 않는다.

| 항목 | 내용 | 발견 |
|------|------|------|
| ★ iOS 소프트 키보드와 토스트 | 화면 아래 고정 토스트는 iOS 에서 소프트 키보드가 열리면 키보드 뒤로 갈 수 있다. 지금은 다루지 않는다 — 에러는 대부분 버튼을 누를 때 나고 그때는 키보드가 닫혀 있다. ★ Phase 3의 채팅 rate limit 처럼 **입력 중에 나는 에러**가 생기면 그때 재검토한다 (`visualViewport` 사용 검토) | R009 (D-032) |
| 토스트 표현 다듬기 | 애니메이션·색·모서리·아이콘. 지금은 140ms 페이드·슬라이드만 넣었다 | R009 |
| 색약 검증 | 플레이어 색상 10종의 실제 구별성 (Q-34) | R004 |
| 키보드 단축키 표기 | Q-56 배정 후 화면 표기 | R002 |

## 2. 향후 확장 후보

구조를 지나치게 하드코딩하지 않되, 미래 기능을 위해 지금을 복잡하게 만들지도 않는다. (guide 52절)

| 후보 | 준비된 것 | 추가로 필요한 것 |
|------|----------|-----------------|
| 객관식 | `questions.question_type` 컬럼 | `question_choices` 테이블, 판정 분기, UI |
| 이미지 퀴즈 | — | `media_url` 컬럼(ALTER로 충분), 저장소, UI |
| 초성 퀴즈 | `question_type`, 초성 변환 로직(힌트에 있음) | 판정 규칙, UI |
| 순서 맞히기 | `question_type` | 판정 규칙, UI |
| 팀전 | — | `game_players` 에 팀 컬럼, 점수 집계 변경, UI |
| 카테고리 선택·제외 | `categories` 테이블, `questions.category_id` | 설정 UI, 문제 선정에 필터 추가 |
| 난이도 선택 | `questions.difficulty` | 설정 UI, 선정 필터 |
| 개인 통계 화면 | **원천 데이터 전부 기록 중** | 집계 쿼리와 UI만 |
| 랭킹 | `game_players` | 집계와 UI |
| 힌트 추가 단계 | `generateHint()` | 규칙 확장 |
| 연속 정답 보너스 | `answer_events` | 점수 규칙 변경 |

**통계가 가장 준비가 잘 되어 있다.** guide 40절이 요구한 9종 지표가 현재 스키마로
전부 계산 가능함을 검증했다([03-DATA-MODEL.md](03-DATA-MODEL.md) 5장).
UI만 만들면 된다.

## 4. Track D — 문제 데이터 확보

| 단계 | 소스 | 예상 확보량 | 라이선스 | 상태 |
|------|------|------------|---------|------|
| D1 | OpenTDB | 약 1,100건 | CC BY-SA 4.0 | 조사 완료 |
| D2 | 위키데이터 템플릿 생성 | 수천 건 | CC0 | 미착수 |
| D3 | ETRI 엑소브레인 QA | 약 569건 | 확인 필요 (승인 절차 있음) | 미착수 |
| D4 | 직접 작성 + AI 보조 | 상시 | CC BY-SA 4.0 | 시드 53건 완료 |

**OpenTDB는 유한 코퍼스다.** API 제공분 5,298건(그중 주관식 전환 가능한 multiple 타입 4,500건)이
전부이고 전량 수확을 이미 완료했다. 생존율이 약 25%라 최종 1,100건 정도다.
**더 긁어도 나오지 않는다.**

**위키데이터가 규모 면에서 유일한 해답으로 보인다.** CC0라 라이선스 제약이 없고
구조화 트리플이라 "정답이 유일하게 결정되는" 문제를 우리가 직접 설계할 수 있다.
단조로워지지 않도록 전체의 일부로만 쓴다.
