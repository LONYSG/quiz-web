## 결정 필요

### Q-53. cloudflared 네트워크 단절 시 URL 유지 여부

**상태**: 확인 필요 (검증 미완)

**배경**: 이 프로젝트의 운영 절차가 여기에 달려 있다.
URL이 유지되면 친구들의 세션 쿠키까지 살아 있어 재로그인 없이 "재개" 만 누르면 되고,
바뀌면 새 링크를 뿌리고 전원이 다시 로그인해야 한다.

**확인된 것**: cloudflared를 **재시작하면** URL이 바뀐다(실측).
로그상 URL은 프로세스 시작 시 1회 발급되고 그 뒤에 개별 연결이 등록되므로,
연결만 끊겼다 재등록되는 경우에는 URL이 유지될 것으로 **추정**한다.

**확인하지 못한 이유**: 네트워크 단절을 강제로 재현하려면 방화벽 규칙이 필요한데
관리자 권한이 없었다. PC 전체 네트워크를 끊는 것은 작업 환경을 해쳐 하지 않았다.

**확인 방법**: 터널을 띄운 상태에서 Wi-Fi를 1~2분 껐다 켠 뒤
(1) 터미널 B가 살아 있는가 (2) 같은 URL로 접속되는가 (3) WebSocket이 재연결되는가.

**영향**: 낮음(운영 절차 문서만 바뀐다). [11-DEPLOY.md](11-DEPLOY.md) 는 이미 두 경우를 모두 적어 두었다.

### Q-54. Gemini 무료 티어의 실제 한도

**상태**: 확인 필요

**배경**: 공식 문서가 무료 티어의 구체 수치 표를 게재하지 않고 "AI Studio에서 본인 한도를 확인하라"고만
안내한다. 제3자 자료 기준 추정으로는 Flash 계열이 일 500~1,500 요청이다.

**확인 방법**: 건우가 Google AI Studio의 rate limit 페이지에서 실제 한도를 확인해 알려준다.

**영향**: 낮음. 배치 크기만 조정하면 된다. Track D 착수 전에 확인하면 된다.

### Q-55. Track D 착수 시점

**상태**: 결정 필요

**배경**: 문제 소모 계산상 1,100건은 생각보다 빨리 소진된다(200문제 게임이면 5판).
그래서 데이터 확보를 게임 완성 후로 미루지 않고 병렬 트랙으로 진행하기로 했다.
그런데 **Gemini API 키가 아직 없어** 실제 착수를 못 하고 있다.

**필요한 것**: (1) Gemini API 키 발급 (2) Q-54 확인
(3) 게임 Phase와 병렬로 언제 진행할지

**영향**: 중간. 게임이 완성돼도 문제가 부족하면 제대로 플레이할 수 없다.
다만 개발·테스트는 시드 53문제로 충분하다.

## 나중에 정해도 되는 것

### Q-56. 키보드 단축키 실제 배정

**시점**: Phase 7 (스킵 투표가 나오는 Phase 4에는 임시 키가 필요하다)

제약이 강하다. 이 게임은 **채팅 입력창에 포커스가 있는 상태가 기본**이므로
일반 문자 키를 쓸 수 없다. 사실상 조합키 또는 기능키만 가능하다.

제안 (실측 후 확정)

| 기능 | 키 |
|------|-----|
| 메시지·답안 전송 | Enter |
| 스킵 투표 토글 | Ctrl+Space 또는 F2 |
| 방장 강제 스킵 | Ctrl+Shift+S 또는 F3 |
| 방장 강제 종료 | Ctrl+Shift+E 또는 F4 |
| 확인창 확인 / 취소 | Enter / Esc |

조합키와 F키를 모두 받아들이고 화면에는 조합키를 표기한다.
Chrome / Edge / Safari에서 충돌 실측이 필요하다.

### Q-57. 응답 시간 통계의 범위

**시점**: 나중

현재 `answer_events` 는 정답 문자열과 일치한 메시지만 저장하므로
**정답을 친 사람의 응답 시간만** 남는다. guide 40절의 예시가 "평균 정답 시간 3.1초" 이므로
요구는 충족하지만, "누가 얼마나 빨리 반응했는가" 같은 지표는 만들 수 없다.

넓히려면 "문제별 첫 메시지 시각" 테이블을 추가한다(기존 컬럼 변경 없이 가능).
모든 채팅을 저장하는 선택지는 채택하지 않는다.

### Q-58. 검수 관리 페이지를 만들 것인가

**시점**: Phase 4 완료 후

Track D의 검수는 당분간 **JSON 파일 직접 편집**으로 한다(파일 기반 파이프라인이라 이게 가장 단순하다).
문제 DB를 본격적으로 채우는 시점에 최소 관리 페이지가 필요할지 판단한다.
`review_queue` 스키마는 이미 확정되어 있으므로 나중에 UI만 얹으면 된다.
