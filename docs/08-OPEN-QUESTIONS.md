### Q-72. ★ 같은 소재로 쏠리는 것을 어떻게 다룰 것인가

**상태**: 결정 필요 (★ R013 에서 **일부만** 해소됐다)

★★ R013 에서 Q-76 이 확정되어 **체감 중복은 게임 쪽에서 막게 되었다** (D-054) —
한 게임 안에서 정답이 겹치는 문제를 내지 않는다.
★ 그래서 (C) 는 더 이상 중복 대책의 전부가 아니다.

★ **그러나 규모 문제는 그대로 남는다.** 게임 쪽에서 막는 것은 "보이지 않게" 하는 것이고,
DB 에 서로 다른 정답이 몇 개나 모이는가는 별개다.
★ 건우 확정(Q-76)대로 소분류를 더 쪼개지 않기로 했으므로 (A) 는 닫혔다.
→ ★ 남은 안은 (B) 뿐이다. 그 비용을 실측해야 한다.

**R012 실측**: 같은 소분류 21개에 양쪽이 각 105건을 만들었더니
정답이 겹친 쌍이 **40쌍**이었다 (통과분 207건 중).

★ 겹치는 것은 대체로 그 소분류의 **가장 대표적인 소재**다 —
가가린, 암스트롱, 히치콕, 구로사와, 컬링, 스키점프, 체크메이트, 스타크래프트 …

★ 이것은 결함이 아니다. **좋은 문제가 먼저 나온 것**이다.
문제는 규모를 늘릴 때 "그 다음" 소재가 얼마나 있는지다.

| 안 | 내용 |
|----|------|
| (A) 소분류를 더 쪼갠다 | ★★ **닫혔다** — Q-76 확정에서 건우가 "중복 때문에 카테고리를 더 쪼개지 말라" 고 정했다 |
| (B) 이미 만든 정답 목록을 프롬프트에 넣는다 | "이 답은 이미 썼다" 를 알려준다. ★ 프롬프트가 길어진다 |
| (C) 겹치면 중복 판정으로 나은 쪽만 남긴다 | ★ 이미 구현되어 있다 (D-047) |

★ 권장: (C) + D-054(게임 안 정답 중복 금지)로 체감 중복을 막고,
규모가 목표에 못 미치면 (B) 를 시도한다.
★ (B)의 비용을 실측해야 한다 — 소분류당 이미 쓴 정답 10~20개를 프롬프트에 넣는 비용.

**영향**: 중간. 수천 건 목표 달성 가능성을 좌우한다.

### Q-67. ★ 인접 중분류의 경계를 어디까지 좁힐 것인가

**상태**: 결정 필요 (카테고리 목록은 건우가 확정한다)

**R011 실측에서 나온 반례 두 개** — 대분류가 달라도 같은 문제가 나왔다.

```
world-geo > 대륙·바다   "지구상에서 면적이 가장 넓은 대양은?"  → 태평양
earth     > 해양        "세계에서 가장 넓은 바다는?"          → 태평양

theatre   > 연극 고전    "셰익스피어 4대 비극 중 하나는?"       → 햄릿
world-lit > 시·희곡      "'사느냐 죽느냐'가 나오는 희곡은?"     → 햄릿
```

★ 건우의 원칙 "다른 카테고리 + 같은 정답 → 문제없음" 의 반례다.
★ 원인은 중분류 두 개가 **같은 축을 공유**하는 데 있다(D-040의 규칙 위반).
경계 문장을 넣었지만 충분히 좁지 않았다.

**선택지**

| 안 | 내용 |
|----|------|
| (A) 경계 문장을 더 좁힌다 | `earth > 해양` = 해류·수온·심해 등 **현상**만 / 바다의 크기·이름은 `world-geo`. `theatre` = 공연·무대·제작만 / 희곡 텍스트는 `world-lit` |
| (B) 중분류를 합친다 | 겹치는 둘을 하나로. ★ 그러면 중분류가 넓어져 후보군이 커진다 |
| (C) 그대로 두고 중복 판정에 맡긴다 | 실측에서 정답 일치로 12쌍 중 11쌍을 잡았다. 검수에서 걸러진다 |

**권장안**: (A) + (C). 경계를 좁히면 발생을 줄이고, 중복 판정이 남은 것을 잡는다.
★ (B)는 하지 않는 편이 낫다고 판단한다 — 중복 2쌍 때문에 트리를 좁히면
"트리를 넓혀 규모를 늘린다" 는 구조 자체가 약해진다.

**★ R012에서 한 것** — (A)를 적용했다.
```
지구과학·기상 > 해양   "★ 해류·수온·조석·심해 등 현상과 구조만.
                        '가장 넓은 바다는?' 처럼 이름·크기를 묻는 문제는 세계 지리로"
세계 지리 > 대륙·바다   "★ 바다와 대륙의 이름·위치·크기·경계만"
공연·연극 > 연극 고전   ★ 소분류를 삭제하고 "연극 사조·연출" 로 바꿨다.
                        희곡 텍스트는 세계 문학으로 보낸다 — 축을 무대로 통일했다
```
★ 효과는 다음 라운드 대량 생성에서 확인된다. 지금은 경계만 좁혔다.

**영향**: 중간. 규모가 커질수록 커진다.

### Q-66. ★ 역검증 불일치를 "표기 변형 후보" 로 볼 것인가

**상태**: 결정 필요 (판정 규칙 변경이므로 실측 근거가 더 필요하다)

**R011 실측 — 역검증 불일치 탈락 2건**

```
"캐나다 국기 중앙의 나뭇잎 종류는?" → 단풍잎
   역검증 답 "단풍나무"    (우리 집합에 "단풍나무 잎" 은 있으나 "단풍나무" 는 없다)

"정팔각형 모양의 규제표지는?"      → 일시정지
   역검증 답 "정지"        ★ "정지" 는 사람이 실제로 칠 표기다. 빠져 있었다
```

★ 두 번째는 **오탈락에 가깝다.** 역검증이 잡은 것은 애매함이 아니라 **빠진 표기 변형**이다.
그런데 현재 규칙은 불일치 + 확신 높음이면 탈락시킨다.

★ 첫 번째는 다르다. "단풍나무" 는 잎이 아니라 나무다. 그것을 정답에 넣으면 안 된다.
→ **두 경우를 자동으로 구분할 방법이 지금은 없다.**

**선택지**

| 안 | 내용 |
|----|------|
| (A) 현행 유지 | 불일치는 탈락. ★ 안전하지만 멀쩡한 문제를 버린다 |
| (B) 불일치도 검수 대기로 | 사람이 "빠진 표기" 인지 "다른 대상" 인지 판단한다. ★ 검수 부담이 늘어난다 |
| (C) 부분 문자열이면 검수 대기 | "정지" ⊂ "일시정지" 처럼 포함 관계일 때만 살린다. ★ "단풍나무" ⊄ "단풍잎" 이라 이 표본에서는 정확히 갈린다 |

**★ 이번 라운드에 고치지 않았다.** 근거: R010에서 역검증 판정을 고쳤다가
정상 문제 6건을 전부 오탈락시킨 경험이 있다. **표본 2건으로 판정 규칙을 바꾸지 않는다.**
탈락한 것은 `processed/` 에 남아 있으므로 규칙을 고치면 `rejudge` 로 회복할 수 있다(D-035).

**권장안**: 표본을 더 모은 뒤 (C). 지금은 (A) 유지.

**영향**: 낮음~중간. 생존율 1% 안쪽이다.

### Q-65. ★ 카테고리 계층 마이그레이션(0003)의 적용 시점

**상태**: 건우 확정 대기 (기술 판단은 끝났다 — D-041)

카테고리 트리를 `categories` 테이블에 넣는 마이그레이션을 **아직 만들지 않았다.**
건우가 R011 샘플을 보고 목록을 확정한 뒤에 만든다.

★ 확정된 설계는 D-041 에 있다 (저장은 소분류 / 통계는 대분류+중분류 / 화면은 대분류).

정보를 잃는 매핑이지만 `processed/` JSON 에 원본이 남아 있어 나중에 채울 수 있다.

**건우가 정할 것**: 카테고리 목록에서 뺄 것 / 추가할 것. 그것이 정해지면 0003 을 만든다.

**영향**: 중간. 통계 화면(guide 40절)의 기반이다.

### Q-63. ★ Gemini 유료 전환 여부 — **전제가 무너졌다. 다시 판단해야 한다**

**상태**: 결정 필요 (운영·비용 판단이므로 혼자 결정하지 않는다)
**건우 입장 (R011)**: 유료 전환하지 않는다. 무료로 어디까지 가는지 먼저 본다.

**★ R010의 근거가 부실했다는 것이 R011에서 드러났다**

R010은 "호출 4회 / 18,236토큰에서 429" 를 근거로 한도가 매우 좁다고 추정했다.
★ 그 수치가 **실제 소비보다 작았다.** 예산 카운터가 두 곳에서 새고 있었다 —
`pipeline-models.mjs`(생 fetch, 아예 세지 않음), `pipeline-compare.mjs`(saveState 누락).
둘 다 R011에서 고쳤다.

**★ R011 실측 (같은 무료 키, 하루)**

| 지표 | R010 | R011 |
|------|------|------|
| API 호출 | 4회에서 429 | ★ **29회, 429 없음** |
| 토큰 | 18,236 | ★ **164,338** |
| LLM 도달 문제 | 20건 | ★ **270건** |
| 최종 통과 | 10건 | ★ **257건** |

★ **하루 한도는 여전히 확인 불가다.** 429 가 나지 않았으므로 257건/일은 **하한**이다.
"하루 한도는 N이다" 라고 쓸 수 없다.

**★ 그리고 병목이 바뀌었다**

무료 한도가 아니라 **카테고리 트리의 너비**가 제약이다.
소분류 294개에 1,000건을 채우려면 소분류당 3.4건인데,
중분류당 3~5건에서 이미 중복이 12쌍 나왔다.
★ 유료로 바꿔도 이 제약은 그대로다. 돈으로 해결되는 문제가 아니다.

**→ 판단**: 지금 유료 전환의 근거가 없다. 무료로 진행하고,
실제로 429 에 막혀 진행이 멈출 때 다시 올린다.
★ 이 항목을 닫지 않고 남겨 두는 이유는 규모가 커지면 다시 부딪힐 수 있기 때문이다.

**영향**: 중간 (R010에서는 높음이었다)

### Q-60. 로컬 `.env` 키와 GitHub Secrets 키가 서로 다른 값이다

**상태**: 확인 필요

**배경**: R005에서 양쪽을 각각 검증했더니 **둘 다 유효하지만 값이 다르다.**

**확인 필요**: 두 값이 같은 프로젝트의 다른 키인가, 아니면 서로 다른 Google 프로젝트인가.
같은 키로 통일할 것인가.

**영향**: 낮음. 다만 키 폐기·회전 시 혼동을 막기 위해 알고 있어야 한다.
