### Q-61. UI 레이아웃 실측 스크립트를 정식 도구로 승격할 것인가

**상태**: 결정 필요 (의존성 추가가 필요하므로 혼자 결정하지 않는다)

**배경**: R007에서 "전송 버튼 글자가 세로로 쪼개진다" 의 원인을 실측하려고
헤드리스 Chrome 을 CDP로 조작하는 스크립트를 만들었다 (`tmp/ui-check.mjs`).

이 도구가 실제로 한 일:

- 지적받은 버튼 외에 **"방 나가기" 버튼의 같은 결함**을 추가로 찾아냈다
- 수정 후 320 / 360 / 390 / 480 / 720px 에서 통과를 확인했다
- 스크립트 자체의 오탐(글자 종류 경계에서 텍스트 상자가 쪼개지는 것)도 실측으로 잡았다

**왜 tmp/ 에 두었는가**: CDP 연결에 `ws` 를 쓰는데, 이것은 socket.io 의
**전이 의존성**이다. 직접 의존성이 아니므로 상위 패키지가 바뀌면 조용히 사라질 수 있다.
정식 도구로 만들려면 `ws` 를 devDependency 로 추가해야 한다.

**선택지**

| 안 | 내용 | 대가 |
|----|------|------|
| (A) 현행 유지 | `tmp/` 에 두고 필요할 때만 쓴다 | 라운드마다 다시 만들거나 잊는다. gitignore 되어 있어 사라진다 |
| (B) `ws` 를 devDependency 로 추가하고 `scripts/ui-check.mjs` 로 승격 | `npm run verify` 에 넣을 수 있다. 라벨 규칙(D-022)이 회귀하면 즉시 잡힌다 | devDependency 1개 증가 |
| (C) Playwright 도입 | 훨씬 강력하다 (실제 IME 조합 이벤트까지 가능할 수 있다) | 브라우저 바이너리 수백 MB. "표준에 가깝게, 의존성 최소" 방침과 거리가 있다 |

**추정**: (B)가 비용 대비 효과가 가장 크다. 다만 R006에서 "의존성을 늘리지 않는다" 가
판단 기준이었으므로 건우가 정할 사안이다.
★ (C)의 "IME 조합을 자동 검증할 수 있는가" 는 **확인 불가**다. 실제로 해 봐야 안다.
현재 그 항목은 사람만 검증할 수 있다고 보고 있다.

**영향**: 낮음. 지금도 사람이 개발자 도구로 같은 것을 확인할 수 있다(절차는 10-TESTING 9장).

### Q-54. Gemini 무료 티어의 실제 한도

**상태**: 확인 필요 (일부 확인됨)

**배경**: 공식 문서가 무료 티어의 구체 수치 표를 게재하지 않고
"AI Studio에서 본인 한도를 확인하라"고만 안내한다.

**R005에서 확인한 것**

- 키는 유효하다. 로컬 `.env` 키와 GitHub Secrets 키가 **서로 다른 값이지만 둘 다 동작한다** (Q-60)
- 응답 헤더에 rate limit 정보가 없다. 429를 실제로 맞아 보지 않으면 한도를 알 수 없다
- ★ **사고(thinking) 토큰이 크다.** 프롬프트 1,481토큰 / 출력 1,291토큰인 요청의
  `totalTokenCount` 가 5,403이었다. 차이 약 2,631이 사고 토큰이다.
  **TPM 한도를 계산할 때 보이는 토큰의 3~4배로 잡아야 한다.**

**남은 확인**: Google AI Studio의 rate limit 페이지에서 RPD / RPM / TPM 확인.

**영향**: 낮음. 배치 크기만 조정하면 된다. Track D 배치 설계 전에 확인하면 좋다.

### Q-59. Track D 에서 쓸 Gemini 모델 확정

**상태**: 결정 필요 (자체 판단으로 잠정 선택함)

**배경**: R002는 `gemini-2.5-flash`(1차 가공) + `gemini-2.5-flash-lite`(역검증)를 전제로 설계했다.
**두 모델 모두 신규 키로는 사용할 수 없다.**
`GET /models` 목록에는 나오지만 `generateContent` 호출 시 404 를 반환한다.

> "This model models/gemini-2.5-flash is no longer available to new users.
>  Please update your code to use models/gemini-3.6-flash"

**잠정 선택** (R005에서 실제로 동작을 확인하고 채택)

| 용도 | 모델 | 근거 |
|------|------|------|
| 1차 가공 | `gemini-3.6-flash` | Google이 에러 메시지에서 직접 권한 모델 |
| 역검증 | `gemini-3.5-flash-lite` | 1차와 다른 모델을 써 같은 방향으로 틀리는 상관관계를 줄인다 |

**확인 필요한 판단 두 가지**

1. **별칭을 쓰지 않기로 했다.** `gemini-flash-latest` / `gemini-flash-lite-latest` 도 동작하지만,
   별칭은 예고 없이 가리키는 모델이 바뀌어 같은 프롬프트가 다른 결과를 내게 되고
   `review_queue.ai_model` 기록의 의미가 사라진다. 명시 버전을 고정한다.
2. **더 최신 모델을 쓸 것인가.** `gemini-3.7-flash` / `gemini-3.8-flash` 도 동작한다.
   품질은 더 좋을 수 있으나 무료 한도가 다를 수 있다(확인 불가).
   3.6이 Google의 권장이므로 그것으로 시작하는 것이 안전하다고 판단했다.

**영향**: 낮음. 설정값이며 되돌리기 쉽다. 다만 프롬프트를 모델에 맞춰 조정한 뒤 바꾸면
결과가 달라질 수 있으니 Track D 착수 전에 정하는 것이 좋다.

### Q-60. 로컬 `.env` 키와 GitHub Secrets 키가 서로 다른 값이다

**상태**: 확인 필요

**배경**: R005에서 양쪽을 각각 검증했더니 **둘 다 유효하지만 값이 다르다.**
(길이가 각각 39자와 53자였다. ★ 값은 어디에도 기록하지 않았다)

의도한 것이라면 문제가 없다. 다만 다음 상황에서 혼동이 생긴다.

- 한쪽 키를 폐기했을 때 다른 쪽이 계속 동작해 "폐기했는데 왜 되지" 가 된다
- 한쪽에만 할당량이 소진되면 원인을 찾기 어렵다

**확인 필요**: 두 값이 같은 프로젝트의 다른 키인가, 아니면 서로 다른 Google 프로젝트인가.
같은 키로 통일할 것인가.

**영향**: 낮음. 다만 키 폐기·회전 시 혼동을 막기 위해 알고 있어야 한다.

### Q-56. 키보드 단축키 실제 배정

**시점**: Phase 7 (스킵 투표가 나오는 Phase 4에는 임시 키가 필요하다)

제약이 강하다. 이 게임은 **채팅 입력창에 포커스가 있는 상태가 기본**이므로
일반 문자 키를 쓸 수 없다. 사실상 조합키 또는 기능키만 가능하다.

제안 (실측 후 확정)

| 기능 | 키 |
|------|-----|
| 메시지·답안 전송 | Enter |
| 스킵 투표 토글 | Ctrl+Space 또는 F2 |
| 방장 강제 스킵 | Ctrl+Shift+S 또는 F3 |
| 방장 강제 종료 | Ctrl+Shift+E 또는 F4 |
| 확인창 확인 / 취소 | Enter / Esc |

조합키와 F키를 모두 받아들이고 화면에는 조합키를 표기한다.
Chrome / Edge / Safari에서 충돌 실측이 필요하다.
