## 2. 봇 클라이언트 (Phase 3 착수 전에 만든다)

**브라우저 창을 10개 띄우는 것은 현실적으로 불가능하다.**
Node에서 `socket.io-client` 로 가상 플레이어 N명을 접속시키는 스크립트가 필요하다.
이것 하나가 아래 테스트의 대부분을 가능하게 한다.

```
scripts/bot.mjs   (미작성)
  --count N       봇 수
  --room ID       접속할 방
  --scenario X    동시 정답 / 연타 / 끊김·재접속 / 지연 전송
```

> 로컬 PC 서버라 메모리 제약이 없어졌으므로 봇 수를 자유롭게 늘릴 수 있다.

## 3. Phase별 필수 테스트

### Phase 1 — 계정 / 방

- [ ] 회원가입·로그인 정상·실패
- [ ] 비밀번호 4자 미만 거부 / 72바이트 초과 거부
- [ ] 닉네임 중복 거부, **대소문자 구분** (`Player` 와 `player` 는 별개)
- [ ] 아이디 대소문자 무시 로그인
- [ ] 10명 정원 초과 입장 거부 → 봇 11명
- [ ] **같은 계정으로 두 번째 접속 시 기존 연결이 끊기고 승계된다**
- [ ] 방장 이탈 → 30초 후 권한 이전
- [ ] **이전 후 원래 방장이 돌아와도 권한을 돌려받지 않는다**
- [ ] 없는 방 / 종료된 방이 각각 다르게 안내된다
- [ ] **1인당 방 1개 제약** — 두 번째 방 생성 거부
- [ ] **서버 재시작 후 방을 다시 만들 수 있다** (부팅 정리 절차)

### Phase 2 — 로비

- [ ] 참가자 목록 실시간 동기화 (봇 입퇴장)
- [ ] 문제 수 경계: 0 / 1 / 200 / 201
- [ ] 카운트다운 경계: 2 / 3 / 60 / 61
- [ ] 카운트다운 취소 → LOBBY 복귀
- [ ] 카운트다운 중 신규 입장 허용
- [ ] **출제 가능 수보다 큰 문제 수로 시작 시 거부 + 안내**

### Phase 3 — 핵심 게임 ★ 가장 중요

- [ ] **동시 정답: 봇 10명이 같은 순간에 동일 정답 전송 → 정답자가 정확히 1명.
      100회 이상 반복해 단 한 번도 2명이 나오지 않아야 한다**
- [ ] **`game_questions.winner_account_id` 로 센 정답 수와
      `answer_events.accepted=true` 로 센 정답 수가 일치한다**
- [ ] 타이머 종료 직전 정답: 29.9초 시점 전송을 반복 → `endsAt` 기준으로 처리
- [ ] **`endsAt` 을 넘겨 도착한 정답은 인정되지 않는다** (tick 오차 구간)
- [ ] 정답 확정 직후 도착한 메시지가 판정되지 않는다
- [ ] **★ RESOLVED 구간 입력이 다음 문제 정답과 일치해도 정답 처리되지 않는다 (epoch)**
      *재현*: 봇이 문제 1의 RESOLVED 구간에 "문제 2의 정답" 을 전송하되,
      전송을 5초 이상 지연시켜 문제 2 시작 직후에 서버에 도달하게 한다
- [ ] 30초 타이머 정확도 측정 (오차 100ms 이내)
- [ ] 한 게임에서 같은 문제가 두 번 나오지 않는다
- [ ] 채팅 rate limit이 **정상적인 연타(초당 3개)를 막지 않는다**
- [ ] 한글 IME 조합 중 Enter가 전송되지 않는다 (브라우저 수동)
- [ ] 10명 × 초당 3개 채팅 부하 → 지연·누락 측정

### Phase 4 — 게임 시스템

- [ ] 힌트가 정확히 남은 10초에 push된다
- [ ] **힌트가 문제 시작 시점에 클라이언트로 전송되지 않는다** (네트워크 페이로드 직접 검사)
- [ ] 스킵 임계값: 활성 1~10명 전 구간 (단위 테스트는 완료. 통합에서 재확인)
- [ ] 투표 중 인원 변동 시 임계값 재평가, 도달 시 즉시 스킵
- [ ] **투표자 명단이 클라이언트로 전송되지 않는다**
- [ ] 스킵과 정답 동시 발생 → 하나만 성립
- [ ] **강제 스킵에 epoch가 담겨, 확인창 사이에 문제가 끝났으면 무시된다**
- [ ] 마지막 문제: 정답 / 시간 종료 / 스킵 세 경우 모두 5초 없이 결과 화면
- [ ] **마지막 문제도 경험 기록이 남는다**
- [ ] 강제 종료 시 진행 중이던 문제의 정답이 공개되지 않고 경험 기록도 없다
- [ ] 다시 하기 후 점수 초기화 + **경험 기록 유지**
- [ ] 동점 공동 순위 (통합)

### Phase 5 — 실시간 안정성

- [ ] 중간 참가: 남은 시간·힌트 상태가 정확히 복원된다
- [ ] **재접속 스냅샷에 남은 시간 10초 초과일 때 힌트가 들어 있지 않다**
- [ ] 접속 종료: 게임 계속, 점수 유지, **스킵 분모 즉시 반영**
- [ ] **"접속 종료" 표시가 5초 후에 나타난다** (새로고침으로 깜빡이지 않는다)
- [ ] 재접속: 점수·색상·경험 여부 유지, 중복 플레이어 미생성
- [ ] 새로고침 반복 (브라우저 수동)
- [ ] 백그라운드 탭 → 복귀 시 타이머 재동기화 (**모바일 실기기 필수**)

#### 일시정지 (PAUSED) ★

- [ ] 활성 0명이 되면 **즉시** PAUSED (유예 없음)
- [ ] **PAUSED 중 타이머가 흐르지 않는다** — 남은 시간이 그대로 유지된다
- [ ] **PAUSED 중 문제가 타임아웃되지 않는다** (경험 기록으로 소모되지 않는다)
- [ ] **자동 재개되지 않는다** — 친구가 들어와도 방장이 누를 때까지 멈춰 있다
- [ ] 재개 시 남은 시간이 정확히 이어진다 (멈춘 값 ± 오차)
- [ ] **재개 시 epoch가 증가하지 않는다** — 같은 문제를 이어서 한다
- [ ] 재개 시 전원의 클라이언트 타이머가 새 종료 시각으로 재동기화된다
- [ ] **PAUSED 중 방 삭제 타이머가 정지한다** — 10분이 지나도 방이 사라지지 않는다
- [ ] **PAUSED 중 방장 이전 타이머가 정지한다**
- [ ] 활성 1명 이상이 되고 방장이 미접속이면 30초 후 방장 이전 → 새 방장이 재개 가능
- [ ] PAUSED 중 채팅은 되지만 정답 판정은 되지 않는다
- [ ] PAUSED 30분 초과 → `abandoned`, 정답 미공개, 경험 미기록
- [ ] PAUSED 중 방장 강제 종료 → `force_ended`
- [ ] COUNTDOWN / QUESTION_ACTIVE / QUESTION_RESOLVED 세 상태 모두에서 PAUSED 진입·재개
- [ ] **실사용 시나리오**: 터널을 끄고 새로 띄운 뒤 새 링크로 전원 재접속 → 재개 → 정상 진행

### Phase 6 — 경험 시스템

- [ ] 처음 보는 문제 / 이미 경험한 문제
- [ ] 경험자의 메시지가 판정에서 제외된다
- [ ] **★ 미경험자가 정답을 치면 마스킹되지 않고 정답 처리된다** (마스킹 오판이 판정을 깨뜨리지 않는다)
- [ ] QUESTION_RESOLVED 이후에는 마스킹하지 않는다
- [ ] 발신자 본인 화면에는 원문 + "가려짐" 표시
- [ ] **마스크 길이가 정답 길이와 무관하게 고정이다**
- [ ] 정규화 매칭 — "고 무 줄" 도 마스킹된다
- [ ] **정답이 2글자 이하일 때 부분 포함으로 마스킹되지 않는다** ("달라졌네")
- [ ] 복수 정답 — 긴 것부터 치환
- [ ] **경험자 닉네임이 전원에게 보인다**
- [ ] **★ 과거 채팅의 마스킹이 문제가 바뀌어도 흔들리지 않는다** (재접속 스냅샷)
- [ ] 강제 종료 후 / 재게임 후 경험 기록 유지
- [ ] 중간 참가자의 경험 처리
- [ ] **RESOLVED 구간 입장자에게 경험 기록이 남는다**
- [ ] 전원 경험 문제만 남은 상황 → 조기 종료 (시드를 소량으로 만들어 재현)
- [ ] `mask.test.ts` 의 skip 13건을 전부 통과시킨다

### Phase 7 — UI/UX

- [ ] **실기기**: iPhone Safari, Android Chrome (터널 URL로)
- [ ] 모바일 키보드가 올라온 상태에서 문제·타이머가 가려지지 않는다
- [ ] **전송 후 키보드가 닫히지 않고 연속 입력이 된다** (iOS에서 특히 까다롭다)
- [ ] 단축키 충돌 실측 (Chrome / Edge / Safari)
- [ ] 단축키가 텍스트 입력을 방해하지 않는다
- [ ] 색상 10종 구분 가능성, 색약 시뮬레이션
