## 0. ★ 매 라운드 마지막에 반드시 할 것

```bash
npm run verify
```

= `typecheck` + `vitest` + `smoke`

> ★ **typecheck 와 build 통과는 실행 가능성을 보장하지 않는다.**
> R005에서 typecheck·build·봇 테스트 21항목이 전부 통과했다고 보고했는데
> 정작 `npm run dev` 가 실행되지 않았다. 둘 다 컴파일까지만 검증하기 때문이다.
> 그래서 "빌드 → 기동 → 응답 → 정상 종료" 를 검증하는 `smoke` 를 만들어 게이트에 넣었다.
> 자세한 경위는 [07-DECISIONS.md](07-DECISIONS.md) D-020 / D-021.

화면이 바뀐 라운드에는 **7장 브라우저 수동 확인**도 함께 한다.
특히 한글 IME 조합 중 Enter 와 모바일 화면은 봇으로 검증할 수 없다.

## 2. 봇 클라이언트

**브라우저 창을 10개 띄우는 것은 현실적으로 불가능하다.**
Node에서 socket.io-client 로 가상 플레이어 N명을 접속시킨다.
★ Phase 3의 동시 정답 100회 반복 테스트가 이것 위에 세워진다.

```bash
npm run bot -- join      --count 11                  정원 초과 확인
npm run bot -- duplicate                             같은 계정 두 번 접속 (Q-06)
npm run bot -- reconnect                             끊고 다시 붙기 + 표시 유예 5초
npm run bot -- host      --grace 36                  방장 이전 (Q-29)
npm run bot -- chat      --count 10 --messages 20    동시 채팅 부하
npm run bot -- lobby                                 ★ Phase 2 설정/권한/경험률
npm run bot -- countdown                             ★ Phase 2 카운트다운/게임 레코드
npm run bot -- empty                                 ★ 활성 0명 동안 카운트다운 보류

  --url    http://localhost:3000   대상 서버
  --prefix bot                     계정 아이디 접두어 (반복 실행 시 바꾼다)
```

봇은 회원가입·로그인을 직접 하고 쿠키를 들고 있다 (Node fetch 에는 쿠키 저장소가 없다).
각 시나리오는 기대값을 **실제로 단정하고** 종료 코드로 성패를 알린다.

> ★ 반복 실행할 때는 --prefix 를 바꾼다. 같은 접두어를 쓰면 이전 실행의 계정과 방이 남아
> ALREADY_HAS_ROOM 이 난다.
>
> 테스트 계정 정리:
> `docker exec quiz-web-db psql -U quiz -d quizweb -c "DELETE FROM sessions; DELETE FROM rooms; DELETE FROM accounts;"`

### Phase 3 — 핵심 게임 ★ 가장 중요

- [ ] **동시 정답: 봇 10명이 같은 순간에 동일 정답 전송 → 정답자가 정확히 1명.
      100회 이상 반복해 단 한 번도 2명이 나오지 않아야 한다**
- [ ] **`game_questions.winner_account_id` 로 센 정답 수와
      `answer_events.accepted=true` 로 센 정답 수가 일치한다**
- [ ] 타이머 종료 직전 정답: 29.9초 시점 전송을 반복 → `endsAt` 기준으로 처리
- [ ] **`endsAt` 을 넘겨 도착한 정답은 인정되지 않는다** (tick 오차 구간)
- [ ] 정답 확정 직후 도착한 메시지가 판정되지 않는다
- [ ] **★ RESOLVED 구간 입력이 다음 문제 정답과 일치해도 정답 처리되지 않는다 (epoch)**
      *재현*: 봇이 문제 1의 RESOLVED 구간에 "문제 2의 정답" 을 전송하되,
      전송을 5초 이상 지연시켜 문제 2 시작 직후에 서버에 도달하게 한다
- [ ] 30초 타이머 정확도 측정 (오차 100ms 이내)
- [ ] 한 게임에서 같은 문제가 두 번 나오지 않는다
- [ ] 채팅 rate limit이 **정상적인 연타(초당 3개)를 막지 않는다**
- [ ] 한글 IME 조합 중 Enter가 전송되지 않는다 (브라우저 수동)
- [ ] 10명 × 초당 3개 채팅 부하 → 지연·누락 측정

### Phase 4 — 게임 시스템

- [ ] 힌트가 정확히 남은 10초에 push된다
- [ ] **힌트가 문제 시작 시점에 클라이언트로 전송되지 않는다** (네트워크 페이로드 직접 검사)
- [ ] 스킵 임계값: 활성 1~10명 전 구간 (단위 테스트는 완료. 통합에서 재확인)
- [ ] 투표 중 인원 변동 시 임계값 재평가, 도달 시 즉시 스킵
- [ ] **투표자 명단이 클라이언트로 전송되지 않는다**
- [ ] 스킵과 정답 동시 발생 → 하나만 성립
- [ ] **강제 스킵에 epoch가 담겨, 확인창 사이에 문제가 끝났으면 무시된다**
- [ ] 마지막 문제: 정답 / 시간 종료 / 스킵 세 경우 모두 5초 없이 결과 화면
- [ ] **마지막 문제도 경험 기록이 남는다**
- [ ] 강제 종료 시 진행 중이던 문제의 정답이 공개되지 않고 경험 기록도 없다
- [ ] 다시 하기 후 점수 초기화 + **경험 기록 유지**
- [ ] 동점 공동 순위 (통합)

### Phase 5 — 실시간 안정성

- [ ] 중간 참가: 남은 시간·힌트 상태가 정확히 복원된다
- [ ] **재접속 스냅샷에 남은 시간 10초 초과일 때 힌트가 들어 있지 않다**
- [ ] 접속 종료: 게임 계속, 점수 유지, **스킵 분모 즉시 반영**
- [ ] **"접속 종료" 표시가 5초 후에 나타난다** (새로고침으로 깜빡이지 않는다)
- [ ] 재접속: 점수·색상·경험 여부 유지, 중복 플레이어 미생성
- [ ] 새로고침 반복 (브라우저 수동)
- [ ] 백그라운드 탭 → 복귀 시 타이머 재동기화 (**모바일 실기기 필수**)

#### 일시정지 (PAUSED) ★

- [ ] 활성 0명이 되면 **즉시** PAUSED (유예 없음)
- [ ] **PAUSED 중 타이머가 흐르지 않는다** — 남은 시간이 그대로 유지된다
- [ ] **PAUSED 중 문제가 타임아웃되지 않는다** (경험 기록으로 소모되지 않는다)
- [ ] **자동 재개되지 않는다** — 친구가 들어와도 방장이 누를 때까지 멈춰 있다
- [ ] 재개 시 남은 시간이 정확히 이어진다 (멈춘 값 ± 오차)
- [ ] **재개 시 epoch가 증가하지 않는다** — 같은 문제를 이어서 한다
- [ ] 재개 시 전원의 클라이언트 타이머가 새 종료 시각으로 재동기화된다
- [ ] **PAUSED 중 방 삭제 타이머가 정지한다** — 10분이 지나도 방이 사라지지 않는다
- [ ] **PAUSED 중 방장 이전 타이머가 정지한다**
- [ ] 활성 1명 이상이 되고 방장이 미접속이면 30초 후 방장 이전 → 새 방장이 재개 가능
- [ ] PAUSED 중 채팅은 되지만 정답 판정은 되지 않는다
- [ ] PAUSED 30분 초과 → `abandoned`, 정답 미공개, 경험 미기록
- [ ] PAUSED 중 방장 강제 종료 → `force_ended`
- [ ] COUNTDOWN / QUESTION_ACTIVE / QUESTION_RESOLVED 세 상태 모두에서 PAUSED 진입·재개
- [ ] **실사용 시나리오**: 터널을 끄고 새로 띄운 뒤 새 링크로 전원 재접속 → 재개 → 정상 진행

### Phase 6 — 경험 시스템

- [ ] 처음 보는 문제 / 이미 경험한 문제
- [ ] 경험자의 메시지가 판정에서 제외된다
- [ ] **★ 미경험자가 정답을 치면 마스킹되지 않고 정답 처리된다** (마스킹 오판이 판정을 깨뜨리지 않는다)
- [ ] QUESTION_RESOLVED 이후에는 마스킹하지 않는다
- [ ] 발신자 본인 화면에는 원문 + "가려짐" 표시
- [ ] **마스크 길이가 정답 길이와 무관하게 고정이다**
- [ ] 정규화 매칭 — "고 무 줄" 도 마스킹된다
- [ ] **정답이 2글자 이하일 때 부분 포함으로 마스킹되지 않는다** ("달라졌네")
- [ ] 복수 정답 — 긴 것부터 치환
- [ ] **경험자 닉네임이 전원에게 보인다**
- [ ] **★ 과거 채팅의 마스킹이 문제가 바뀌어도 흔들리지 않는다** (재접속 스냅샷)
- [ ] 강제 종료 후 / 재게임 후 경험 기록 유지
- [ ] 중간 참가자의 경험 처리
- [ ] **RESOLVED 구간 입장자에게 경험 기록이 남는다**
- [ ] 전원 경험 문제만 남은 상황 → 조기 종료 (시드를 소량으로 만들어 재현)

| 6 | 부팅 정리 절차 실행 | `[boot]` 로그 확인 |
| 7 | `GET /` 가 클라이언트 HTML 서빙 | 오리진 1개 구성이 실제로 동작하는지 |
| 8 | Socket.IO 핸드셰이크 | |
| 9 | 프로세스 종료 + 포트 해제 | 남으면 다음 실행이 EADDRINUSE 로 실패한다 |

> ★ 종료 코드가 0인지는 보지 않는다. Windows 에서 `child.kill()` 은 즉시 종료라
> 자식의 SIGTERM 핸들러가 실행되지 못하고 `code=null / signal=SIGTERM` 이 된다(실측 확인).
> 그래서 "프로세스가 사라지고 포트가 해제되는가" 만 본다.
> 사람이 터미널에서 Ctrl+C 를 누르는 경로는 이 스크립트로 재현할 수 없어 확인하지 못했다.

★ `npm run bot` 도 서버가 안 떠 있으면 **사람과 같은 경로**(`server/dist/index.js`)로
직접 띄운 뒤 테스트하고 끝나면 종료한다. 테스트가 실제 실행 경로와 달라지지 않게 하기 위함이다.
`--no-boot` 을 주면 직접 띄우지 않는다.

### (3) ★★ 한글 IME 조합 중 Enter — 가장 중요

> 이 게임은 0.1초로 승부가 갈리므로, 조합 확정 Enter가 전송으로 처리되면
> `훈민정` 같은 미완성 글자가 날아간다. **봇으로는 검증할 수 없다.**

**절차**

1. 채팅 입력창을 클릭한다
2. 한/영 키로 **한글 입력 모드**로 바꾼다
3. `훈민정음` 을 친다. **마지막 글자 `음`을 치고 나면 `음`이 아직 조합 중인 상태다**
   (글자에 밑줄이나 커서 강조가 보이는 상태)
4. 그 상태에서 **Enter를 한 번 누른다**
5. 이어서 **Enter를 한 번 더 누른다**

**정상이면 보이는 것**

- 4번의 Enter는 **조합을 확정만 하고 아무것도 전송하지 않는다.**
  채팅 로그에 새 줄이 생기지 않는다
- 5번의 Enter에서 **`훈민정음` 전체가 한 번** 전송된다
- ★ 채팅에 `훈민정` 이나 `훈민정음` 이 두 번 나타나면 **버그다**

**같이 확인**

- 전송 후 입력창에 커서가 그대로 남아 있어 바로 다음 글자를 칠 수 있다
  (매번 입력창을 클릭해야 하면 버그다 — guide 14·42절)
- 100자를 넘겨 입력할 수 없다
- 영문 모드에서 Enter는 한 번에 바로 전송된다

### (4) 휴대폰(LTE) 접속과 좁은 화면

1. **4번 터미널**을 열고 `npm run build` → 그다음 `npm run dev:tunnel`
   (터널은 3000번 서버를 공개하므로 클라이언트가 빌드되어 있어야 한다)
2. 출력된 `https://….trycloudflare.com` 주소를 휴대폰으로 연다
   ★ **Wi-Fi를 끄고 LTE로** 열어야 외부 접속 검증이 된다
3. 휴대폰에서 새 계정(`test3` / `민수`)으로 가입해 초대 링크로 방에 들어간다

**정상이면 보이는 것**

- https 로 열리고 경고가 없다
- 참가자 목록이 세로로 잘 쌓이고 닉네임·배지가 줄바꿈으로 깨지지 않는다
- 채팅 로그 높이가 화면을 넘지 않는다(200px 정도로 줄어든다)
- 하단 정보(오프셋/RTT)가 세로로 정렬된다
- PC 창에도 `민수` 가 즉시 나타난다
- 채팅이 PC ↔ 휴대폰 양방향으로 즉시 오간다

**모바일 키보드 확인**

- 입력창을 탭해 키보드가 올라와도 채팅 로그와 전송 버튼이 가려지지 않는다
- 전송 버튼을 탭해 메시지가 나가고 키보드가 닫히지 않는다

**접속 종료 표시도 함께 확인**

- 휴대폰에서 브라우저 탭을 닫는다
- PC 화면의 `접속 1명 → 2명` 표시(활성 인원)는 **즉시** 줄어든다
- 반면 `민수` 옆의 **`접속 종료` 배지는 약 5초 뒤에** 나타난다
  ★ 즉시 나타나면 새로고침할 때마다 표기가 깜빡이므로 5초 유예를 둔 것이다 (Q-15)
- 방장 화면에는 `민수` 옆에 **내보내기** 버튼이 생긴다
