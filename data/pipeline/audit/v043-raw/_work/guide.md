# V043 지시서 — 주제 세트 변형 완전성 (제안 하나하나가 곧 정답 판정이 된다 → 의심스러우면 넣지 않는다)

게임: 많이 말하기·겹치면 무효·빙고·캐치마인드 채팅 정답·라이어 키워드. 플레이어가 입력칸에 **실제로 칠 표기**를 `name`/`variants` 로 판정한다.
판정 = 퀴즈와 같은 normalizeAnswer(공백 제거·대소문자·전각/반각) + flex(괄호·가운뎃점/마침표/쉼표 제거·영문 관사 the/a/an·끝맺음 "이다/입니다/요/임"은 제출 쪽만).
**이미 같은 것으로 받는 꼴은 제안하지 않는다**: 띄어쓰기만 다른 것, 대소문자만 다른 것, 괄호 안 덧붙임, 가운뎃점 유무, 숫자 앞 띄어쓰기("아이언맨 2"="아이언맨2"). (하이픈 · 조사 · "시/구" 붙인 꼴 · 로마 숫자 Ⅱ 는 받지 않는다 — 이런 건 제안 대상.)

## 제안 add (variant) — 항목당 ≤ 4, 한국에서 실제로 치는 표기만
① 정규화로 안 받아지는 띄어쓰기/붙임·하이픈 꼴 ② 약칭·줄임(맨유 · 토트넘 · EPL) ③ 옛 이름·다른 공식 표기(구단 옛 이름은 세트가 '계보' 로 묶을 때만 — kbo-team 꼴 · 나라 옛 이름 X) ④ 한글 음차 흔한 꼴("어벤져스"↔"어벤저스", "스파이더맨"↔"스파이더 맨"은 이미 받음) ⑤ 행정구역 "주/시/군/구/역/도" 뺀 꼴(이미 있으면 제외) ⑥ 로마자·숫자 표기 차이
**넣지 않는다**: 오타·틀린 맞춤법 · 영문 번역어/영문 일반어(영문은 사람·작품 이름의 영문 표기와 원소 기호 2글자만 — 단, 구단·기업 약칭은 `latinAbbr:true` 로 따로 표시) · 넓은 말(북극곰←곰) · 설명 꼴("~하는 동물") · 다른 항목과 겹칠 수 있는 말(한 글자·두 글자 흔한 말) · 안 쓰는 한글 음차 · 질문을 베끼는 꼴.

## 제안 remove (variant-remove) — 지금 있는 변형 중
다른 항목의 name/변형과 canon 겹침(topics-check 가 이미 막는다 — 남은 건 "넓은 말" 위주) · 넓은 말 · 설명 꼴 · 옛 답/틀린 답 · 영문 번역어(라틴 변형 예외 밖) · 사실이 아닌 별명. 근거 없이 지우지 말 것.

## 좋은 예 8
1. 영등포구: add "영등포" (구 뺀 꼴)  2. 맨체스터 유나이티드: add "맨유" (약칭)  3. 어벤져스: add "어벤저스" (음차 두 꼴)
4. 스파이더맨 홈커밍 : add "스파이더맨 홈 커밍" 은 이미 공백 무시로 받음 → 제안 안 함(좋은 판단)  5. 강남역: add "강남" (역 뺀 꼴)
6. 카자흐스탄: add "카자흐" (일상 약칭, 다른 나라와 안 겹침)  7. 아이언맨 2: 제안 없음(숫자 띄어쓰기는 받음)  8. 쿠알라룸푸르: add "쿠알라룸프르" 는 오타라 X, 대신 "쿠알라룸푸르" 만 유지
## 나쁜 예 8
1. 오타 "에어콘"(에어컨) ✗  2. 넓은 말 "곰" ← 북극곰 ✗  3. 이미 받는 꼴 "대한 민국" ✗  4. 영문 번역어 "Seoul" ← 서울 ✗  5. 설명 꼴 "유럽에서 제일 큰 나라" ✗
6. 한 글자 흔한 말 "중" ← 중구 ✗  7. 옛 나라 이름 "버마" ← 미얀마 (세트가 계보로 안 묶음) ✗  8. 세트 밖 항목과 겹치는 약칭 "리버풀"(도시 vs 구단은 해당 세트 안에서만 판정이므로 OK) — 세트 안 겹침만 본다

## 출력
각 청크마다 JSON 파일(경로는 지시에 있음) 하나:
{"chunk":"<이름>","sets":{"<slug>":{"items":N,"proposals":[{"id":"<slug>-NNN","name":"..","add":["..",".."],"remove":[{"v":"..","why":".."}],"reason":"항목당 한 줄","latinAbbr":false,"conf":"high|mid"}],"unsure":["id: 이유"]}}}
- 제안 없는 항목은 적지 않는다(전부 ok 로 간주) — 단 **모든 항목을 한 번씩 눈으로 봐야** 한다(items 수와 본 수를 맞출 것).
- label 이 있는 항목(통화·MCU 등): label 의 표기가 name/variants 의 canon 에 없으면 add 로 제안(label 은 판정에 안 쓰인다).
- 확신 낮은 것은 add 에 넣지 말고 unsure 에. 웹은 거의 쓰지 않는다(전체 ≤ 3회, 표기가 정말 쓰이는지 확인할 때만) — 표기 지식으로 본다.
- 세트 파일을 고치지 마라. 읽기 전용. 결과 JSON 파일만 쓴다.
