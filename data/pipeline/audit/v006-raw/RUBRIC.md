# V006 판정 기준 (판정자 전부가 같은 파일을 쓴다) — R036 중(3) 일반 힌트 1,328 · 이미 게임에 나가는 힌트

## 상황
- 한국어 주관식 퀴즈 게임. 문제 40초 — 남은 30초에 **일반 힌트가 혼자 15초** 보이고, 남은 15초부터 초성 힌트가 더 붙는다. 먼저 맞힌 한 사람만 점수. 정답 공개 뒤 해설 5초.
- 이 1,328 건은 난이도 **중(3)** 문항의 일반 힌트다 (GEN 이 R036 에 hint-v3 로 만들어 **이미 DB 에 적재**됐다). 우리는 판정만 하고, 고칠 것은 **제안 힌트 전문**을 쓴다. 반영은 GEN(G002)이 한다.
- 입력 항목: `id · question · answer · variants(인정되는 다른 답) · explanation(정답 공개 뒤 보이는 해설, 없을 수 있다) · hint(판정 대상) · path(힌트의 길: 연결/유래/쓰임/무리/기타) · gen(GEN 이 "셀 수 있다" 고 표시한 것 — 결과에 영향 주지 말 것) · sameAnswerIn(같은 정답인 다른 id — 함께 보되 따로 판정) · hintCheck(기계 경고 — 참고)`.
- ★ 중(3)은 **질문만으로도 풀릴 수 있는** 문제다(H11). 그래서 힌트가 대상을 가려내는 "두 번째 줄 사실" 이면 정상이고, 그 힌트로 아는 사람이 더 빨리 맞히는 것은 **fix 사유가 아니다**.

## 정본 규칙 (docs/15-QUALITY-STANDARD.md §4-1 — 요지)
- **H2** 정답 글자·조각을 보여 주지 않는다 — 정답·변형·정답을 이루는 낱말(한글 2글자 이상)·로마자/음차 조각. (기계 검사 block 은 0 이었다 — 사람 눈으로 음차·풀어 쓴 조각을 본다)
- **H3** 질문에 이미 있는 정보를 되풀이하지 않는다 (낱말 몇 개가 겹치는 것이 아니라 **같은 정보**를 다시 말하는 것).
- **H4** 해설과 **같은 사실**을 쓰지 않는다 — 해설 같은 정보는 괜찮다. 낱말이 겹쳐도 주장이 다르면 ok (예: 힌트 '대처 총리' / 해설 '말비나스라 부른다' → 다른 사실). 힌트가 해설의 주장을 미리 말해 버리면 fix.
- **H5** 사실이어야 한다. 확신 없는 어원·단정(처음·유일·모두·연도)은 출처가 있어야 한다.
- **H6** 이름의 유래(인물·지명·그리스어·라틴어)를 풀어 **질문과 엮어 추리하게** 하는 것은 좋은 힌트다.
- **H9 ★★★ 세기** — 도와주기(ok) / 떠먹여 주기(fix). **판정 문장: "힌트만 읽고(질문 없이) 보통 한국 성인에게 바로 답이 떠오르는가."** 기준 사람은 **보통 한국 성인**이다 — 모델 자신이 아니다. "셀 것 같다" 는 느낌은 unsure 가 아니라 **ok** 다.
- **H10** 정답과 같은 대상의 **다른 이름**(우리말·원어·번역어·옛 이름·본명·약칭)을 힌트에 쓰지 않는다 — 그 이름을 친 사람이 오답이 되면 불공정. 변형에 들어 있으면 H2(full) 로 더 분명한 fix. 고치는 길은 힌트에서 빼기(변형 추가 아님).
- **H11** 보이는 시간 — 혼자 15초는 한 번 생각하기에 넉넉하다 → 힌트는 한 걸음 생각이 필요한 쪽.
- **Q-108 (shape)** — 힌트가 정답의 **꼴**(글자 수 · 언어 · 외자 여부 · '○○' 빈칸 · "한자어다/영어 낱말이다")을 말하는 것은 **결정 전**이다. **이것만으로 fix 하지 않는다.** categories 에 `shape` 를 붙이고, 꼴 말고 다른 사실이 없으면 `shape-only` 도 붙인다. H9 에도 걸리면 그건 평소대로 fix.

## ★ 보정 표본 10건에서 고정한 선 (판정자가 그대로 쓴다)
1. **H9 판정은 문장 그대로** — 힌트만 따로 읽어 보고, 질문을 모르는 보통 성인이 그 힌트에서 바로 답을 말할 수 있으면 fix. 질문의 재료가 있어야 답이 완성되면 ok.
   - ok 예: 야수파 ← '드랭과 블라맹크가 함께했고 활동은 3년 남짓' · 클라리넷 ← '모차르트가 말년에 협주곡과 5중주' · 밀 ← '아버지의 조기 교육, 여성 권리 책' · 헤파이스토스 ← '아프로디테의 남편' · 국제사법재판소 ← '총회와 안보리가 뽑는 재판관 15명' · 미야자키 ← '다카하타 이사오와 스튜디오를 세움' (지브리를 말하지 않았다 — 한 번 생각이 필요) · 포클랜드 ← '당시 영국 총리 대처, 아르헨티나 군사 정권 붕괴 계기'.
   - fix 예: 쇼팽 ← '폴란드에서 태어나 파리에서 활동, 마주르카·폴로네즈' (정체 그 자체) · 바로크 ← '음악에서는 바흐와 비발디' · 9 ← '그가 완성한 교향곡 가운데 마지막 번호' · 청소년보호법 ← '편의점에서 술·담배 살 때 나이 확인 근거' · 소닉 ← '고슴도치를 본뜬 캐릭터' · 튤립 ← '17세기 네덜란드 알뿌리 투기 광풍'.
2. **H9 ① 뜻풀이·번역** — 힌트가 **정답 낱말(또는 정답을 이루는 낱말)의 뜻·번역을 그대로** 적어 어휘만 알면 답이 되는 것 → fix (`meaning`). 진폭 변조 ← "앞에는 파동이 흔들리는 폭을 가리키는 말" · 문화 지체 ← "뒷부분은 '제때보다 늦어짐' 을 뜻하는 한자어" · 레온 ← '스페인어로 사자' · 피벗 ← '방향을 돌리라는 뜻의 영어'.
   - 반대로 **이름의 짜임·유래 규칙만** 말하고 재료는 질문에서 가져와야 하는 것은 ok(H6): 커피 벨트 ← "'Corn Belt' 처럼 작물 이름 뒤에 '띠' 를 뜻하는 영어" · 펜홀드 ← '손으로 쥐는 모양을 그대로 영어로 옮긴 것' · 뿌리혹박테리아 ← '사는 자리와 만드는 것, 미생물 갈래를 이어 붙인 이름'. 보통 사람이 모르는 그리스어·라틴어·한자 어원(실러캔스 ← "그리스어로 '속이 빈 가시'")도 ok. **유래가 다른 이름·다른 대상을 거쳐 가면** ok (모르핀 ← 꿈의 신 모르페우스).
   - 가르는 질문: "힌트의 그 구절을 그대로 우리말/영어 낱말로 바꾸면 정답(의 낱말)이 되는가" → 그러면 fix.
3. **H9 ② 가장 유명한 것 하나** — 대표곡('Smells Like Teen Spirit' → 너바나) · 대표 상징(책상 스탠드 로고 → 픽사) · 정체 그 자체(폴란드 피아노 작곡가 → 쇼팽 · 고슴도치 캐릭터 → 소닉) · 가장 유명한 사건·기능(튤립 파동 → 튤립 · 술·담배 나이 확인 → 청소년보호법) · 유명 줄거리 요지 → fix (`famous-one`). 두 번째 줄 사실(조연 인물 · 다른 작품 · 젊은 시절 · 숫자 · 제도의 세부)은 ok.
4. **늘 fix (세기와 무관)** — H2 글자·조각(`letters`) · H10 다른 이름(`alias`) · H5 사실 아님(`error`) · H4 해설과 같은 사실(`explain-overlap`) · H3 질문 되풀이(`question-repeat`).
5. **ok 가 기본값** — 중(3) 힌트의 대부분은 ok 가 정상이다. "세다" "아는 사람은 바로 안다" 만으로 fix 하지 않는다(교훈 B — 이 사유의 fix 34건이 되돌려졌다). 애매하면 unsure 로 두고 이유를 적는다.

## 길(path)마다 특히 볼 것
- **유래(311)** → ①/H6 경계. 뜻풀이·번역 그대로인가, 짜임·어원 설명인가.
- **연결(747)** → ②. 연결한 사실이 그 대상의 가장 유명한 것(대표작·대표곡·창업자·대표 사건·정체)인가.
- **무리(100)** → 같은 무리를 나열하다가 **정답이나 정답의 다른 이름**이 들어가지 않았는가(H2·H10). 나열한 것 중 하나가 정답과 같은 대상인가.
- **쓰임(108)** → H3. 질문이 이미 쓰임을 말했는데 힌트가 같은 쓰임을 되풀이하지 않는가.
- **기타(62)** → 위 전부.

## 사실(H5) 확인 방식 (C)
- 힌트의 **주장마다** facts 항목을 쓴다 (연도 · 이름 · 숫자 · 관계 · "처음/유일" 같은 단정 — 힌트 한 개에 보통 1~3 주장).
- 먼저 자신이 확신하는 주장은 `result:"true", basis:"knowledge", doubt:false`. **조금이라도 의심되는 주장(연도 · 숫자 · 세부 직함·위치 · 단정어 · 잘 모르는 소재)은 `doubt:true` 로 표시하고 전부 웹으로 확인**한다 — WebFetch 로 `https://ko.wikipedia.org/wiki/<제목>` · `https://en.wikipedia.org/wiki/<Title>` 을 직접 연다(나무위키는 자주 403 — 위키백과 우선). WebSearch 는 **조각당 8회 이내**. 웹으로 확인한 주장은 `basis:"web", source:URL, result: true|false|unverified`(페이지에서 못 찾으면 unverified — 거짓이 아니다).
- 틀린 주장(false)이 있으면 verdict fix(`error`) + 제안 힌트.

## 제안 힌트 (fix 일 때)
- **한 문장 · 120자 이내 · 줄바꿈 없음** · 정답 글자·조각·다른 이름 없음 · 해설의 주장을 미리 말하지 않음 · 질문을 되풀이하지 않음 · 꼴(글자 수·언어)을 말하지 않음.
- 떠먹여 주기였으면 **두 번째 줄 사실**로 바꾼다. 가능하면 원래 힌트의 문제 부분만 빼고 나머지를 살린다.
- 제안에 **새로 넣은 사실**은 facts 에 `proposal:true` 로 따로 적고, 가능하면 웹 확인(basis web + source). 못 했으면 knowledge.

## 결과 (항목마다 한 객체 · **입력 순서 그대로 · 개수 같게** · id 로 기계 대조한다)
```json
{"id":748,
 "verdict":"ok|fix|unsure",
 "categories":["spoon-feed","meaning","famous-one","letters","alias","error","explain-overlap","question-repeat","shape","shape-only"],
 "hintAlone":"힌트만 읽은 보통 성인이 떠올릴 답 — 떠올리면 그 답, 아니면 '못 떠올림'",
 "proposal":{"hint":null},
 "reason":"한국어 1~2줄 — 무엇을 봤고 왜 그 판정인지 (fix 면 어느 규칙)",
 "facts":[{"claim":"…","result":"true|false|unverified","basis":"knowledge|web","source":null,"doubt":false,"proposal":false}],
 "shape":null}
```
- categories 는 fix·unsure 일 때 사유, ok 일 때는 `shape` 만 들어갈 수 있다(비어도 된다). `spoon-feed` 는 ①②에 들지 않는 떠먹여 주기.
- 판정 근거에 "질문에 ~라고 적혀 있다" 를 쓸 때는 **입력 원문에서 확인한 것만** 쓴다(교훈 A). 추측을 사실처럼 쓰지 않는다.
- `gen` 표시와 `hintCheck` 는 참고일 뿐 판정을 바꾸지 않는다. `blind` 는 주지 않았고 쓰지 않는다.
