  ★ 화면마다 각자 지우지 않는다. D-027 이 그렇게 만들어진 것과 같은 이유다.

  `viewKey` 를 계산하고, 그 값이 바뀌면 알림을 지운다.

    viewKey = 'loading' | 'terminated' | 'auth' | `room:<방ID>` | 'home'

  ★ 방 ID 를 키에 넣었다. 방을 옮기는 것도 화면 전환이다.

  ★ 선언 순서가 중요하다.
    이 effect 는 에러 effect 보다 **먼저** 선언되어야 한다.
    한 커밋에서 둘이 함께 실행되면 나중에 선언된 쪽이 이긴다.
    에러 때문에 화면이 바뀌는 경우가 있으므로 **에러가 살아남는 편이 안전하다.**
    코드에 그 이유를 주석으로 남겼다.

  "에러의 원인이 해소되었을 때" 를 **코드별로 짝짓지 않았다.**
  (예: NOT_ENOUGH_QUESTIONS 를 문제 수 변경과 짝지어 지우는 것)

  (1) ★ **화면 전환 + 자동 만료로 이번 증상이 전부 해결된다.**

3-1. ★ "보인다" 를 DOM 존재로 판정하지 않는다

  ★ 이것이 이번 라운드에서 도구에 대해 배운 것이다.

    R008의 배너는 **DOM 에 있었다.** 스크롤을 내리면 화면 밖이었을 뿐이다.
    ★ DOM 검사만 하는 테스트였다면 통과했을 것이다.
      즉 R008의 ui-check 는 이번 결함을 잡지 못했다.

  → 요소의 **화면 좌표**를 구해 판정한다.

    getBoundingClientRect() → { top, bottom, left, right }
    뷰포트: window.innerWidth / innerHeight
    fullyVisible = top >= 0 && left >= 0 && bottom <= vh && right <= vw

  겹침도 같은 방식으로 사각형 교차를 계산한다.

    overlap = ra.left < rb.right && ra.right > rb.left
           && ra.top < rb.bottom && ra.bottom > rb.top
