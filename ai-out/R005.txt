      오리진이 하나이므로(서버가 클라이언트를 직접 서빙) None 이 필요 없고,
      None 은 서드파티 쿠키로 분류되어 모바일 사파리에서 차단될 수 있다.
      Lax 면 초대 링크 클릭(top-level navigation)에도 쿠키가 붙는다.

  [Q-06 — 계정당 활성 소켓 1개]
    · 계정별 현재 소켓을 Map으로 관리한다.
    · 새 연결이 들어오면 기존 소켓에 session.terminated { reason: 'another_connection' } 를
      보내고 강제로 끊는다.
    · ★ 승계된 소켓의 disconnect 핸들러가 새 소켓의 매핑을 지우지 않게 했다.
      (socketByAccount.get(accountId) === socket.id 확인)
      이 확인이 없으면 승계 직후 새 연결이 매핑에서 사라져 다음 승계가 동작하지 않는다.
    · ★ 세션 레코드는 계정당 여러 개를 허용한다(R003 4-1 확정).
      제한하는 것은 소켓 연결이다. 세션을 1개로 하면 폰에서 로그인하는 순간 PC가 로그아웃된다.
    ★ 나중에 붙이면 재접속 로직 전체를 다시 봐야 하므로 지금 넣었다.

4-3. 방 (C-3)

  server/src/db/rooms.ts, server/src/socket/index.ts

  · 생성 / 입장 / 퇴장. 정원 10명. 1인당 동시 1개(DB 부분 UNIQUE가 강제).
  · rooms.id 는 randomBytes(12).toString('base64url') = 16글자, 96비트.
    무작위 대입으로 찾을 수 없다.
  · ★ 초대 링크는 클라이언트에서 window.location.origin + /r/<roomId> 로 만든다.
    서버 환경변수에서 읽지 않으므로 터널 URL이 바뀌어도 서버 재시작이 필요 없다.
  · ★ guide 49절: 없는 방과 종료된 방을 구분한다.
    메모리에 없으면 DB를 조회해 closed_at 으로 판별한다.
      ROOM_NOT_FOUND  "존재하지 않는 방입니다."
      ROOM_CLOSED     "이미 종료된 방입니다."
  · 방 제목 1~30자 (R001 8-11 승인분).
  · ★ 방 생성도 INSERT 후 제약 위반을 잡는다. 제약명(rooms_one_open_per_owner_idx)으로 판별한다.

4-5. ★ 메모리 방 관리 구조 (C-5) — 이번 라운드에서 가장 중요

  Phase 3의 게임 상태가 이 구조 위에 얹힌다.

  [rooms/types.ts]
    Room / Player / RoomSettings / ChatEntry.
    ★ game / currentQuestion / paused 필드를 미리 선언해 두었다(지금은 항상 null).
      Phase 3에서 채우기만 하면 되고, 스냅샷 생성 함수도 구조를 바꿀 필요가 없다.
    ★ Player 에 disconnectedAt 을 둔 이유: 표시 유예 5초 계산의 근거다.
      connected(즉시)와 표시(5초 뒤)를 분리하기 위해 필요하다.
    ★ ChatEntry 에 rawNfc 와 maskedText 를 함께 둔다.
      마스킹은 브로드캐스트 시점에 확정하고 여기에 저장한다.
      스냅샷에서 재계산하면 문제가 바뀔 때 과거 메시지의 마스킹이 흔들린다(R003 3-4).

  [rooms/registry.ts]
    방 레지스트리(Map) + 계정→방 인덱스.
    ★ 이 파일의 함수는 전부 동기다. DB 접근이 필요한 것은 db/rooms.ts 에 분리했다.
      ★ 이 분리를 유지하는 것이 "판정 블록에 await 를 넣지 않는다"를 지키는 실질적 장치다.
      파일 상단에 Phase 3에서 지켜야 할 4개 규칙을 주석으로 남겼다.
    · activeCount()  — 끊김 즉시 반영. 스킵 분모가 이 값을 쓴다
    · pickColorIndex() — 쓰이지 않은 가장 작은 인덱스
    · addPlayer()    — 이미 있으면 재연결로 처리. 색상·점수 유지. 방장 권한은 건드리지 않는다
    · nextHostCandidate() — 입장 순서가 가장 빠른 활성 플레이어

  [tick.ts] 전역 100ms tick
    ★ 방마다 setTimeout 을 두지 않는다.
    현재 검사: 방장 이전 / 접속 종료 표시 / 방 삭제
    ★ Phase 3~5에서 들어올 것을 주석으로 명시했다(COUNTDOWN 만료, 힌트 push,
      문제 종료, RESOLVED 5초, PAUSED 30분).
    ★ tick 콜백에서 await 를 쓰지 않는다. DB 쓰기는 void 로 띄우고 기다리지 않는다.
      그러지 않으면 tick 이 밀려 "정확히 30초"가 깨진다.
    ★ 한 방의 오류가 다른 방의 tick 을 멈추게 하지 않는다(try/catch).
    ★ 방 삭제 조건에 PAUSED 정지 조건을 미리 넣었다. Phase 1에는 PAUSED가 없지만
      빼먹으면 Phase 5에서 일시정지가 무의미해진다.

  [socket/guard.ts] 인바운드 공통 검사
    ★ on() / onRoom() 헬퍼로 검사 순서를 강제한다.
      seq 부여 → 세션 → 방 소속 → 권한 → 상태 → 페이로드 스키마
      개별 핸들러가 검사를 빼먹을 수 없게 만드는 것이 목적이다.
      핸들러는 이미 검증된 컨텍스트(Ctx / RoomCtx)만 받는다.
    ★ 핸들러 예외가 프로세스를 죽이지 않는다. 게임 중 한 사람의 요청 처리 실패가
      방 전체를 날리면 안 된다.
    에러 코드 10종과 한국어 메시지를 한 곳에 모았다.

  [rooms/emit.ts]
    emitRoom / emitRoomPerPlayer / emitToPlayer / emitToSocket / disconnectSocket.
    ★ emitRoomPerPlayer 는 Q-25(경험 배지)와 Q-35(마스킹)가 의존하는 구조다.
      지금 만들어 두면 Phase 6에서 구조 변경이 없다.
    ★ overrideFn 은 반드시 동기 함수여야 한다는 것을 주석에 명시했다.

  [rooms/snapshot.ts]
    buildSnapshot() — reason: join | reconnect | resync 단일 페이로드.
    게임 관련 필드(countdown / question / paused / skip / result / experienceRates)는 null.
    ★ displayConnected() 를 별도 함수로 분리했다.
      표시용 connected(5초 유예)와 판정용 activeCount(즉시)를 혼용하지 않게 하는 장치다.
      주석에 "스킵 분모에는 이 함수를 쓰지 않는다"를 명시했다.
    ★ toChatView() 가 마스킹을 재계산하지 않고 저장된 값을 그대로 쓴다.

  [seq.ts]
    프로세스 전역 단조 카운터. number. 재시작 시 0부터.

9-1. 이번 라운드 자체 판단 항목

  기술적이고 되돌리기 쉬운 것만 결정했다. 이견이 있으면 알려주면 즉시 바꾼다.

  계정·세션
  · 아이디 3~20자, 영문 소문자·숫자·_·- 만 허용 (D-018에 근거 기록)
  · 닉네임 1~12자, 제로폭·제어문자·연속 공백 불허 (D-018)
  · 로그인 실패는 사유를 구분하지 않고 회원가입은 구분한다 (D-019)
  · 중복 검사를 SELECT 없이 INSERT + UNIQUE 위반으로 처리한다
  · SESSION_SECRET 을 세션 토큰 해시의 HMAC 키로 쓴다 (D-017)
  · 쿠키 Secure 를 요청 프로토콜에 따라 분기하고 SameSite=Lax 로 고정한다 (D-017)
  · argon2 구현체로 @node-rs/argon2 를 쓴다 (사전 빌드 바이너리. Windows 빌드 위험 없음)
  · 쿠키 파싱을 직접 한다 (cookie-parser 의존성을 늘리지 않는다. 6줄이면 된다)

  방·구조
  · rooms.id 는 randomBytes(12) base64url (16글자, 96비트)
  · 초대 링크 경로를 /r/<roomId> 로 정했다
  · 마지막 참가자가 나가면 tick 의 10분을 기다리지 않고 즉시 방을 정리한다
  · 한 사람이 두 방에 동시에 있을 수 없다 (계정→방 인덱스로 강제)
  · room.playerJoined 등에 참가자 목록 전체와 activeCount 를 동봉한다 (04-PROTOCOL에 근거 기록)
  · room.playersUpdated 이벤트를 신설했다 (표시 전환 순간 알림)
  · tick 이 표시 상태 서명(signature)을 비교해 바뀔 때만 브로드캐스트한다

  Gemini·검증
  · 1차 가공 gemini-3.6-flash / 역검증 gemini-3.5-flash-lite (Q-59로 확인 요청)
  · 별칭 모델(gemini-flash-latest)을 쓰지 않는다
  · 키를 x-goog-api-key 헤더로 보낸다 (쿼리스트링은 프록시·서버 로그에 남는다)
  · 에러 본문을 scrub() 으로 통과시켜 키 문자열을 무조건 치환한다
  · 검증 워크플로에 schedule 트리거를 두지 않는다

  기타
  · .ps1 은 UTF-8 BOM + CRLF (PowerShell 5.1 제약). .gitattributes 에 예외 규칙 추가
  · maskAnswers() 는 호출 시 "Phase 6에서 구현한다" 에러를 던진다
    (빈 구현으로 두면 조용히 잘못 동작한다)
