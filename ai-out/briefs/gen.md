■ 2. 정답 표기 후보 목록(기계 · DB 쓰기 0) — ★ **사전이 먼저 · 위키는 그다음**(찬종 2026-11-18: "위키백과로 먼저 거르는 게 맞아?" — 아니다. 위키로 먼저 거르면 "위키도 우리와 같은 틀린 표기를 쓰는 것"을 놓치고, 기준이 아닌 것이 문지기가 된다)
  · 대상: quizweb 의 활성 문항 전부의 `display_answer`(7,367장쯤 · 같은 정답은 한 번만). `skip` = 숫자 · 연도 · 문장형 답 · 괄호 설명이 붙은 답 · 영문 · 숫자만으로 된 답(사전에 물을 수 없는 것).
  · **가. 전부를 표준국어대사전에 묻는다 — ★ 국립국어원 오픈 API 로**(찬종 2026-11-18: "국립 국어원 api 있어? 그럼 그걸 쓰는 게 좋잖아. 장기적으로도." · 안내 = https://stdict.korean.go.kr/openapi/openApiInfo.do — 쓰기 전에 한 번 열어 아래가 맞는지 · 하루 호출 한도 · 이용 조건을 확인하고 보고에 적는다):
    - 키: `.env` 의 `STDICT_API_KEY`(찬종이 넣는다 · 값은 화면 · 로그 · 파일에 찍지 않는다 · 캐시 파일에 요청 주소를 남길 때 키는 뺀다). **키가 없으면 가~라 는 하지 않는다** — 1(5222 변형)만 하고 "키가 없어 사전 조회를 건너뜀"으로 보고하고 끝낸다(웹 화면을 긁어서 대신하지 않는다).
    - 요청: `https://stdict.korean.go.kr/api/search.do?key=…&q=<낱말>&req_type=json&method=exact`(검색 · 기본이 exact) — 응답에서 **글자가 똑같은 표제어가 있는지**(사전은 표제어에 `-` · `^` 를 넣어 적는다 — 그 기호와 띄어쓰기를 빼고 견준다) · 있으면 그 표제어의 원어 · 뜻 한 줄도 같이 저장.
    - 요청 사이 0.3초 · 하루 한도의 절반을 넘기지 않는다(한도를 넘을 양이면 나눠서 — 어디까지 했는지 보고) · 결과는 `data/pipeline/audit/g101-raw/dict/` 에 캐시(끊겨도 이어서 · 다시 돌려도 다시 묻지 않는다).
    - ★ **두고두고 쓸 도구로 만든다**: `scripts/dict-check.mjs` — 낱말 목록(파일 또는 DB 의 활성 정답)을 받아 사전에 묻고 `{word, found, headword, origin}` 을 돌려준다(캐시 공유). 다음부터 새 카드를 실을 때 정답 표기를 이 도구로 한 번 보게 하려는 것 — 적재 게이트에 붙이는 것은 이번에 하지 않는다(쓰는 법만 docs/16 의 GEN 도구 목록에 한 줄).
    - `dict-ok` = 똑같은 표제어가 있다 → 끝(고칠 것 없음)
    - `dict-no` = 없다 → 나 로
  · **나. 사전에 없는 것만 위키백과에 묻는다**(한국어 위키백과 API `action=query&redirects=1&titles=…` · 한 번에 50개 · 요청 사이 0.5초 · 캐시 `g101-raw/wiki/`):
    - `same` = 그 이름의 문서가 있다(고유 이름 · 작품 · 전문용어일 가능성 — 표기 문제 신호 없음)
    - `redirect` = 다른 표제어로 넘겨진다 → 글자 차이로: ⓐ 띄어쓰기 · 가운뎃점 · 괄호만 다르다 ⓑ **한두 글자만 다르다** ⓒ 아주 다른 이름이다
    - `none` = 문서도 없다
  · **다. ⓑ 의 위키 표제어를 다시 사전에 묻는다**(같은 API · 같은 도구): 사전에 있으면 `fix`(★ **고칠 후보** — 우리 표기는 사전에 없고 한두 글자 다른 표기가 사전에 있다) · 없으면 `look`(사전에 둘 다 없다 — 사람이 볼 것).

  · 이 방법이 놓치는 것(보고에 그대로 적는다): 우리 표기가 사전에 없고 위키도 우리와 같은 표기를 쓰는데, 사전에는 다른 표기로 실려 있는 낱말 — 기계로는 못 찾는다. `same` 가운데 고유 이름이 아닌 보통 낱말(분류가 인물 · 작품 · 지명 · 상표가 아닌 것)의 수와 본보기 30개를 따로 적어 둔다.
