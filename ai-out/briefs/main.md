■ 확정 (찬종 결정 — 설계 권장안 채택)
- 뽑기는 **아직 갖지 않은 것 중에서 무작위** — 중복이 나오지 않는다. 테마를 다 모으면 "완성" 표시, 뽑기 버튼 비활성. 환불·재뽑기 규칙은 필요 없다.
- 특별 이모티콘도 **10칸(Alt+1~0)에 넣을 수 있다** ("자유롭게 사용").
- 표시: ★ **떠 있는 큰 반응** — 보내면 **채팅 입력창 바로 위**(PC·모바일 같은 자리 · 기존 emoji-flash 가 아니라 모두에게 보이는 층)에 크게(약 96px) 떠서 **3초** 뒤 사라진다. 동시에 최대 **3개**가 옆으로 쌓이고(4번째가 오면 가장 오래된 것부터 밀린다) 보낸 사람 닉네임(색)을 작게 붙인다. **채팅 로그에는** 기존 이모티콘처럼 "닉네임 + 작은 그림(32px — 표준 24 보다 조금 크게)" 한 줄만 남긴다(올려 봐도 누가 보냈는지 보이게). **PC 참여자 칸**은 지금 이모티콘 자리(64px) 그대로 특별 이모티콘도 보인다. 로그를 밀어내지 않고 모바일에서도 보인다.
  ★ 찬종이 "실제로 봐야 알 것 같다" 고 했으므로 **대안도 그림으로** — 같은 장면을 "로그 안에 크게(96px 한 줄)" 로 찍은 것을 한 세트 더(코드는 표시 방식 상수 하나로 갈라 두고 기본은 떠 있는 반응). 보고서 0절에 두 그림을 나란히 보여 찬종이 고르게 한다.

- 뽑기 흐름: 버튼 → `POST /api/shop/draw {themeKey}` → 서버 **한 트랜잭션**(잔액 다시 계산 → 부족이면 409 · 미보유 목록에서 무작위 1 → account_emojis INSERT · point_spends INSERT(reason 'gacha' · ref 'theme:<key>/emoji:<id>')) → {emoji, balance, owned, total}. 클라이언트는 응답을 **받은 뒤** 갓챠 애니메이션(캡슐이 흔들리다 열리며 그림이 커진다 — 약 1.5초 · 누르면 건너뜀 · 효과음은 기존 정답 코인 소리 재사용) → 결과 카드("새 이모티콘! 치이카와 3 · 7/27") → [한 번 더] [닫기]. 애니메이션은 CSS 만(라이브러리 없음). 효과음은 효과음 음량을 따른다.
- 뽑은 뒤 클라이언트 카탈로그 갱신: `/api/emoji` 를 다시 받아 cache 교체(`qw:emoji-catalog` 이벤트 그대로).
- ★ **다른 사람 화면에서 그리는 문제** — 지금 `/api/emoji` 는 **가진 특별 이모티콘만** 내려보내서, A 가 보낸 특별 이모티콘을 B 는 카탈로그에 없어 못 그린다. 고침: 목록은 **전원에게 모든 활성 특별 이모티콘의 메타(id · 이름 · themeId)** 를 주고, 응답에 `ownedSpecial: number[]` 를 따로 준다. 고르기 창 "특별" 탭과 10칸 등록은 owned 만, 그리기는 전부. 서버의 보내기 차단(미보유 BAD_REQUEST)은 그대로. 그림 URL(`/api/emoji/:id/image`)은 지금처럼 공개.
- 고르기 창: 분류 탭 맨 앞에 **✨ 특별** 탭(가진 것이 하나라도 있을 때만 보임 — custom 탭과 같은 방식) · 테마별 작은 머리글 · 누르면 바로 보냄 · "칸 바꾸기" 로 10칸에 넣기. 10칸에 든 특별 이모티콘을 나중에 잃을 일은 없다(뺏지 않는다).
- 보내기: 같은 `emoji.send`(번호) — 서버가 특별이면 SPECIAL 창·잠금으로 세고 `chat.throttled {kind:'special'}`. 채팅 로그 항목에 `special: true` 를 붙여(스냅샷 · 재접속 포함) 클라이언트가 표시 방식을 가른다. 소리는 표준과 같은 "뽀잉".
- 떠 있는 반응 층: 채팅 입력줄 바로 위, throttle-note 와 같은 문서 흐름이 아니라 **겹쳐 뜨는 층**(화면 배치를 밀지 않음 — 한 화면 규칙 R035). 모바일은 키보드가 올라와 있어도 입력창 위에 보이게. 테마 파스텔·밤 둘 다.
