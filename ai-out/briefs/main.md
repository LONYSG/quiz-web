■ 할 일
A. **라이어 — 간결하고 분명하게**(찬종 폼: 토론 **60초** · 짧은 화면은 **없애고 단계 줄**)
  1. **단계 줄**: 판 화면 맨 위에 늘 보이는 한 줄 — `① 설명 → ② 토론 → ③ 투표 → ④ 변론 → ⑤ 결과`. 지금 단계를 강조(색 · 굵기)하고 그 옆에 남은 시간과 "지금 할 일" 한 마디(예: "○○ 님이 설명할 차례" · "라이어라고 생각하는 사람을 고르세요" · "○○ 님의 변론을 들어 보세요"). 재투표 · 죽일지/살릴지 · 맞히기 · 이의제기는 ③ · ④ · ⑤ 안의 작은 글자로(단계 수를 늘리지 않는다). PC · 폰 둘 다.
  2. **자유 토론 단계 새로**(`discuss` · `DISCUSS_MS: 60_000`): 설명 한 바퀴가 끝나면 60초 토론 → 투표. 화면에는 모든 사람의 설명 줄을 한눈에(누가 무엇이라고 했나) + 채팅. **[토론 끝] 버튼** — 접속한 사람의 **과반**이 누르면 바로 투표로(누른 수 / 필요한 수 표시). 투표 바퀴가 다시 돌 때(살렸을 때)도 투표 앞에 토론을 둔다(이때는 30초 — 상수 `REDISCUSS_MS`).
  3. **스쳐 가는 화면 없애기**: ⓐ `assign`(5초) — 따로 띄우지 않는다. 역할 · 주제 · 키워드 카드는 **설명 단계 화면 안에 내내 보이게** 하고, 첫 차례 시작 전에 3초 "곧 시작" 만 같은 화면에서 센다(화면이 바뀌지 않는다). ⓑ `tally`(4초) — 따로 띄우지 않는다. 투표 결과(누가 누굴 찍었나)는 **다음 단계 화면(변론 · 재투표) 위쪽에 접히지 않는 줄로 남긴다.** ⓒ `appeal`(8초) — 맞히기 오답 화면 안의 버튼으로만(화면 전환 없음 · 시간은 공개 화면이 뜨기 전 8초 그대로 두되 그동안 공개 화면의 뼈대가 이미 보이게). 단계 사이에 **빈 화면 · 깜빡임 · 1~2초짜리 전환이 남아 있으면 전부 찾아서 없앤다**(실제로 한 판을 돌려 단계가 바뀌는 순간마다 찍어 본다 — 보고서에 단계별 그림).
  4. **시간 늘리기**: `VOTE_MS 15 → 20초` · `REVOTE_MS 10 → 15초` · `FINAL_MS 10 → 15초` · `GUESS_MS 15 → 20초` · `REVEAL_MS 7 → 10초`. `SAY_MS 20초` · `DEFENSE_MS 20초` 는 그대로(말한 사람이 끝내면 넘어가는 지금 동작 유지). 모두가 고르면 남은 시간과 상관없이 바로 넘어가는 동작이 지금 없으면 넣는다(투표 · 죽일지/살릴지 · 이의 투표).
  5. 규칙 문서 · 판 안 도움말 · 봇 시나리오 · 단위 테스트를 새 단계에 맞춘다. 기록(`liar_rounds` 등)에 토론 단계가 필요 없으면 칸을 늘리지 않는다.
B. **채팅창 크기 + 스크롤 0**(찬종 폼: "그 중간으로 하는데, 채팅이 최소 5개? 적절한 라인은 최소한 보여주도록 해. 5줄은 그냥 예시야. 사진이나 컨텐츠 크기에 맞게 최대한 키우면서 채팅창이 너무 적게 보이지는 않는 최적의 경우를 찾아. **어떠한 경우에도 화면에 스크롤이 생기면 안돼.** 지금 125% 배율 fhd 기준으로 스크롤이 너무 자주 생겨.")
  1. **규칙을 숫자로 못박는다**(상수 · CSS 변수 한 곳에): ⓐ 페이지(문서) 스크롤 **0** — 어떤 화면 · 어떤 단계에서도 `document.scrollingElement.scrollHeight <= innerHeight`. 넘칠 것은 **내용이 줄어든다**(표지 · 그림 · 카드가 남은 높이에 맞춰 작아지고, 글은 줄 수 제한 + 줄임) — 페이지가 늘어나지 않는다. 채팅 목록 **안**의 스크롤만 허용. ⓑ 채팅은 **보이는 메시지 줄이 최소 6줄**(입력 칸 빼고 · PC 기준 — 높이가 모자란 창에서는 내용 쪽을 더 줄인다) ⓒ 너비는 R094 이전과 지금의 **중간**에서 시작해, 내용(표지 · 그림 · 문제 카드)을 가장 크게 하면서 ⓐ · ⓑ 를 지키는 값으로 맞춘다 — 화면마다 따로 손으로 맞추지 말고 **같은 배치 규칙 하나**(내용 = 남은 높이에 맞춰 줄어드는 칸 · 채팅 = 최소 높이/너비 보장)를 퀴즈 · 노래 · 미니게임 · 라이어 · 캐치마인드 · 결과 · 로비에 쓴다.
  2. **검사를 먼저 만든다**(고치기 전에 지금 빌드에서 빨간불이 나오는지 확인): 창 크기 `1536×864`(= FHD 125%) · `1536×730`(브라우저 탭 · 주소 · 북마크 줄을 뺀 실제 높이) · `1920×1080` · `1920×945` · `1280×720` · `2560×1440` × 화면(로비 · 방 설정 · 퀴즈 문제 / 힌트 / 공개 · 노래 듣는 중 / **정답 공개** / 결과 · 미니게임 판 / 공개 · 라이어 각 단계 · 캐치마인드 그리는 중 / 공개 · 판 결과) — ① 페이지 스크롤 0 ② 채팅 보이는 줄 ≥ 6 ③ 내용이 잘리지 않음(표지 · 그림 · 정답 글자가 다 보임). 이것을 `ui-check` 묶음 하나(r101)로 남겨 다음 라운드들도 돌린다.
  3. 찬종이 짚은 곳부터: **노래 정답 공개 화면**(1536×730 에서 스크롤) · 노래 듣는 중의 채팅. 보고서 0절에 화면마다 고치기 전 / 뒤 나란히(채팅 줄 수 · 내용 크기 숫자와 함께).
  4. 폰 배치는 건드리지 않는다(이번 제보는 PC) — 다만 스크롤 0 검사는 `360×740` 에서도 한 번 돌려 지금 상태를 보고서에 적는다(고치지는 않는다).
C. **캐치마인드**(찬종: 선착순 한 명 · 시간 더 길게(폼: **120초**) · 포기 버튼)
  1. **먼저 맞힌 한 명이 나오면 그 그림은 바로 끝**(공개로). 점수: 맞힌 사람 **+2** · 그린 사람 **+1** · 아무도 못 맞히면 둘 다 0(설계 판단 — 옛 "맞힌 순서 3 · 2 · 1" 은 뜻이 없어져 지운다 · 바꾸기 쉽게 상수로). 규칙 문서 · 판 도움말 · 결과 화면의 점수 설명을 같이 고친다.
  2. `ROUND_MS 90 → 120초`.
  3. **포기 버튼**(그리는 사람만 · 도구 줄 옆 · 기존 버튼 꼴): 누르면 확인 한 번("이 그림을 포기할까요?") → 그 그림 끝(점수 0 · 공개 화면에 "출제자가 포기했어요" + 제시어) → 다음 사람. `다른 제시어`(처음 10초)는 그대로 둔다. 포기 횟수 제한은 두지 않는다.
  4. 봇 시나리오 · 단위 테스트(첫 정답에 끝 · 동시에 둘이 맞혔을 때 서버가 먼저 받은 한 명만 · 포기 · 출제자 끊김).
