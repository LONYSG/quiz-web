1-1. Q-62 (B) 확정 규칙을 구현했다

    · 429 → 15분 대기 → 1회 재개. 또 429 면 그날 중단
    · 대기 시간을 설정값으로 뒀다 — LIMITS.rateLimitWaitMs

    · 재개 횟수 상한도 설정값이다 — LIMITS.maxResumesPerDay = 1

  ★ 재개 이력과 구간별 소비를 상태 파일에 기록한다 (작업 B 원천 데이터)

    data/pipeline/state/daily.json 에 항목을 넣었다.

      segments[]       ★ 429 사이 구간마다 건수·토큰·호출·429로 닫혔는지

    ★ 왜 구간을 나눠 기록하는가

    ★ 오래된 상태 파일(R010 형식)에는 segments 가 없다. 그 경우에도 동작한다.
      상태 파일 형식 때문에 파이프라인이 멈추면 안 된다.

3-1. ★ 중복 검사 기준 계층 판단과 근거

  (가) 세 계층을 실제 트리에 대본 결과

    |---------|-----|--------------------------------------------------------|
    | 소분류  | 294 | 후보군이 너무 좁다. 같은 중분류의 다른 소분류로 흩어진 중복을 놓친다 |
    | 중분류  | 63  | ★ 채택                                                  |
    | 대분류  | 7   | 후보군이 너무 넓다. 자연과학 정답 "3" 이 무관한 문제들과 충돌한다   |

    ★ 설계 담당(건우 측)의 제안 "중분류에서 검사, 소분류에서 생성" 을 검토했다.
      → **그 제안이 맞다.** 채택했다. 약점은 (나)에 적는다.

  (나) ★★ 그런데 건우가 든 반례는 계층 문제가 아니었다

    "훈민정음을 만든 왕?"  (한국사 > 조선 전기)
    "한글을 창제한 왕?"    (한국 문화유산 > 기록유산)

    ★ 이것은 **중분류 검사의 결함이 아니라 카테고리 목록의 결함**이다.

      "한국 문화유산" 이라는 중분류가 존재하는 순간,
      조선 시대 유물 문제는 한국사에도 문화유산에도 **합법적으로** 들어간다.
      ★ 어느 계층에서 검사하든 이 목록으로는 막을 수 없다.
        소분류로 검사해도 못 잡고, 중분류로 검사해도 못 잡는다.

    → 그래서 규칙을 하나 세웠다.

      ★★ **중분류는 하나의 주제 축으로만 나눈다.**
         같은 대상을 다른 축(인물 / 유물 / 명작 / 기록)으로 다시 묶는
         중분류를 만들지 않는다.

    이 규칙으로 초안에서 뺀 것
      · 인물(위인·현대 유명인) — ★ 정답이 인물인 문제는 거의 모든 중분류에서 나온다
      · 건축·유적의 "유적" — 유적 문제는 해당 시대의 역사 중분류로 보낸다
      · (한국 문화유산은 초안에 없었으나 만들 뻔했다. 시대 소분류로 흡수했다)

    ★ 즉 **카테고리 목록 자체가 중복 검사 장치의 일부**다.
      목록이 틀리면 검사 계층을 아무리 잘 골라도 소용없다.

  (다) 실제 구현 — 세 단계 (pipeline/src/dedupe.ts)

      1단계  정규화한 정답으로 **후보를 좁힌다**  (shared 의 normalizeAnswer 재사용)
      2단계  카테고리로 **의심 강도**를 정한다   (같은 중분류 > 같은 대분류 > 다른 대분류)
      3단계  질문 문장 유사도로 **"같은 정답 다른 문제" 를 구분한다**

    ★ 건우의 "문장을 하나하나 판단하는 것은 비효율" 은 **전수 비교**를 말한 것으로 읽었다.
      실측: 257건의 전수 비교는 32,896쌍. **정답으로 좁힌 뒤 후보는 12쌍.**
      후보만 문장을 비교하는 비용은 사실상 0이다.

    ★ 유사도는 문자 2-그램 자카드다. 단어 단위가 아닌 이유:
      한국어는 조사가 붙어 단어 경계가 흔들린다.
      "한글을 창제한" 과 "한글의 창제자" 는 단어로는 하나도 겹치지 않는다.

  (라) ★★ 실측이 3단계를 반박했다. 그대로 적는다.

    3단계(유사도)는 "같은 정답 다른 문제" 를 구분하려고 넣었다. **못 했다.**

      실제 중복인 쌍의 유사도    0.13 / 0.28 / 0.29 / 0.32 / 0.43 / 0.50
      실제로 다른 문제인 쌍       0.00

    ★ 모델이 문장을 완전히 바꿔 쓰기 때문에 같은 문제여도 유사도가 0.13까지 내려간다.
    ★ 0.13과 0.00 사이에 선을 그으면 이 표본(8쌍)에서는 완벽히 갈린다.
      **그러나 그것은 과적합이다.** 표본 8쌍으로 임계값을 정하지 않았다.
      임계값(0.55)을 그대로 뒀다.

    ★ 다만 유사도가 쓸모없지는 않다 — 완전 동일 판정(exact)은 확실히 작동한다.
      따옴표만 다른 같은 질문 1쌍을 잡았다. 그것은 판정이 아니라 동일성이다.

  (마) ★★ 그리고 건우 원칙의 반례가 나왔다

    "다른 카테고리 + 같은 정답 → 대체로 문제없음" 이 **성립하지 않은 쌍이 3쌍**이다.

      world-geo > 대륙·바다   "지구상에서 면적이 가장 넓은 대양은?"  → 태평양
      earth     > 해양        "세계에서 가장 넓은 바다는?"          → 태평양
        ★ 대분류가 다른데 같은 문제다

      theatre   > 연극 고전    "셰익스피어 4대 비극 중 하나는?"      → 햄릿
      world-lit > 시·희곡      "'사느냐 죽느냐'가 나오는 희곡은?"    → 햄릿
        ★ 중분류가 다른데 같은 작품이다

    ★ 그리고 **유일한 무해 사례는 오히려 같은 중분류 안에 있었다.**

      world-language > 외래어 어원     "'빵'은 어느 나라 언어에서 왔는가?"  → 포르투갈어
      world-language > 세계 언어 분포   "브라질의 유일한 공용어는?"         → 포르투갈어
        ★ 같은 중분류인데 완전히 다른 문제다. 둘 다 살려야 한다

    | 관계                    | 쌍 수 | 실제 중복 |
    |-------------------------|------|----------|
    | 같은 중분류 + 같은 정답   | 9    | 8        |
    | 다른 중분류 + 같은 정답   | 3    | ★ 3      |
    | 합계                    | 12   | 11 (91.7%) |

    ★★ 관측 결론: **정답이 겹치면 카테고리와 무관하게 거의 항상 중복이었다.**
       이 표본에서는 카테고리 계층이 중복 여부를 예측하지 못했다.

    → **수정된 권고**
       · 후보 추리기는 **정답 일치만으로** 한다. 카테고리로 후보를 자르지 않는다
       · 카테고리는 **자동 폐기 판단에 쓰지 않고 의심 강도(정렬)** 에만 쓴다
       · ★ 위 두 반례는 다시 카테고리 목록의 문제다 → Q-67 로 올렸다

    ★ 표본이 12쌍이다. 규모가 커지면 흔한 정답(숫자·나라 이름)에서
      무해한 충돌이 늘 것으로 **추정**한다. 그때는 카테고리 정렬이 값을 한다.

  (바) ★ 자동 폐기 vs 검수 대기 판단 (지시 항목)

    ★ **검수 대기다. 자동 폐기하지 않는다.**

    근거
      · R010에서 내가 만든 역검증 판정 로직이 정상 문제 6건을 **전부** 오탈락시켰다.
        판정 로직은 틀린다
      · 버리면 회복에 토큰이 든다. 남기면 사람이 한 번 보면 된다.
        ★ 비용이 비대칭이다
      · ★ 부수 이득: 중복 후보는 **표기 변형 추가 후보**이기도 하다
        (R010에서 실제로 그렇게 "드럼 세트"/"드럼킷" 을 얻었다)

    ★ 예외 하나 — 정규화한 질문까지 완전히 같으면 그것은 판정이 아니라 **동일성**이다.
      그 경우만 exact 로 표시해 자동 폐기 후보로 둔다. 실측 1쌍이 여기 해당한다.

3-2. 카테고리 흔들림 방지 설계 (C-2)

  ★ 카테고리를 **생성 요청의 입력**으로 만들었다. 모델이 정하는 값이 아니다.

    R010까지는 모델이 골랐다 — "[생성 4] category — 다음 중 하나: …"
    ★ 그러면 같은 문제가 라운드마다 다른 카테고리로 분류될 수 있고,
      카테고리가 흔들리면 **중복 검사의 기준 자체가 흔들린다.**

  구현
    · 슬롯 단위로 [대분류 > 중분류 > 소분류] 를 지정해 보낸다
    · 모델은 slotId 만 되돌려 준다
    · ★ 기록하는 카테고리는 **우리가 요청한 값**이다. 모델 응답에서 읽지 않는다

  ★ 그러나 모델이 "이 카테고리로는 못 만든다" 고 말할 여지는 남겼다 (offCategory).
    억지로 만든 문제가 실전에 나가는 것이 더 나쁘다. 그 경우는 탈락이고 사유를 남긴다.

  ★ 실측 결과 (270슬롯)
    offCategory      0건
    슬롯 누락        0건
    카테고리 어긋남  ★ **0건** — 통과한 257건을 직접 읽어 확인했다

  ★ 부수 효과 하나: 슬롯을 지정하니 **소분류를 돌려 쓸 수 있게 되었다**(subOffset).
    오프셋 없이 두 번 돌리면 같은 소분류를 다시 요청해 중복이 난다.
    ★ "트리를 넓혀 규모를 늘린다" 는 구조가 이것으로 성립한다.

    accessibility (접근성) — **이 분야를 일반적인 한국 성인이 아는가.** 1~5
      5 = 한국의 초·중·고 교과 과정이나 국민 대다수가 아는 대중문화

4-3. ★ 샘플로 확인된 것

  (가) 카테고리가 입력일 때 실제로 그 카테고리에 맞는 문제가 나오는가 (C-2 검증)

    ★ **나왔다. 어긋난 사례 0건이다.**

      | 지표             | 값   |
      |------------------|------|
      | 슬롯 요청         | 270  |
      | 모델 반환         | 270  |
      | 슬롯 누락         | 0    |
      | offCategory 선언  | 0    |
      | ★ 어긋난 사례     | ★ 0  |

    ★ 통과한 257건을 직접 읽어 요청한 소분류와 대조했다. 표본이 아니라 전수다.
    ★ 다만 하나 짚어야 한다 — **소분류 사이의 침범은 있었다.**
      "서양 애니메이션" 슬롯이 픽사 문제를 만들었다(4-2 참조).

    ★ 원인: 승급 대상이 그룹당 1~2건인데 그것 때문에 호출 하나를 통째로 썼다.

      ★ 이번 샘플은 고치기 전 방식으로 생성되었다. 다음 실행부터 적용된다.

    ★ 토큰은 줄었을 것으로 **추정**한다. 근거는 R010 프로브에서 같은 프롬프트에

  ★ 1단계와 2단계에 같은 모델을 쓰지 않는다. **생성에 쓴 모델도 제외한다**(pickBackcheckChain).
