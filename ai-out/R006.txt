4-1. scripts/smoke.mjs — 실행 확인

  ★ typecheck·build 가 잡을 수 없는 것을 잡는다.

  검증 9항목
    1. npm run build 성공
    2. 서버 산출물 존재      ← tsbuildinfo 함정 감지
    3. 클라이언트 산출물 존재  ← 없으면 터널 접속 시 빈 화면
    4. ★ 서버 기동 + /healthz 200   ← R005에서 빠져 있던 검증
    5. healthz 필수 필드 (ok / phase / bootedAt)

    7. GET / 가 클라이언트 HTML 서빙  ← 오리진 1개 구성이 실제로 동작하는지
    8. Socket.IO 핸드셰이크
    9. 프로세스 종료 + 포트 해제      ← 남으면 다음 실행이 EADDRINUSE

  ★ npm start 와 완전히 같은 명령으로 띄운다. 별도 경로를 만들지 않았다.

  ★ 이 스크립트를 처음 돌렸을 때 스크립트 자체의 오탐 1건이 나왔다.
    "SIGTERM 정상 종료 — 8초 내에 종료되지 않아 강제 종료함" 으로 실패했는데,
    실제로는 서버가 정상 종료되고 있었다.
    원인: 종료 판정을 exit 콜백의 code 만으로 했다. Windows 에서 child.kill() 은
    즉시 종료(TerminateProcess)라 code=null, signal='SIGTERM' 이 온다.
    code 만 보면 "신호로 종료됨"과 "아직 안 죽음"이 둘 다 null 이라 구분되지 않았다.
    → signal 을 함께 추적하고, 판정 기준을 "프로세스가 사라지고 포트가 해제되는가" 로 바꿨다.

    ★ 부수 확인(실측): Windows 에서 child.kill() 로는 자식의 SIGTERM 핸들러가 실행되지 않는다.
      사람이 터미널에서 Ctrl+C 를 누르는 경로는 이 스크립트로 재현할 수 없어
      **확인하지 못했다(확인 필요).** 포트 해제와 프로세스 소멸은 어느 경로든 동일하므로
      그것만 검증한다. 이 한계를 문서에 적었다.

  ★ 전문은 docs/10-TESTING.md 7장에 있다. 다음에도 그대로 쓸 수 있다.
    아래는 같은 내용의 요약이다.

5-1. 준비 — 터미널 3개

    1번 창   npm run db:up        DB 컨테이너. 한 번 뜨면 이 창은 비워도 된다
    2번 창   npm run dev          서버
    3번 창   npm run dev:client   클라이언트 개발 서버

  2번 창에 이렇게 나오면 정상이다.
    [dev] 첫 빌드…
    [dev] 빌드 완료
    [dev] 감시 시작. …
    [boot] 정리할 잔여 방/게임 없음
    ┌──────────────────────────────────────────────┐
    │  퀴즈 서버 기동  http://localhost:3000       │
    └──────────────────────────────────────────────┘

  3번 창에는 Local: http://localhost:5173/ 이 나온다.

5-2. ★ 접속할 주소 — 혼동하지 말 것

    개발 중 화면 확인   http://localhost:5173      ★ 이걸 쓴다. 고치면 즉시 반영
    빌드 결과 확인      http://localhost:3000      서버가 직접 서빙 (npm run build 후의 화면)
    친구들과 플레이      https://….trycloudflare.com  4번 창 npm run dev:tunnel. (4)번 확인에만 필요

  ★ 5173 과 3000 은 로그인 세션이 서로 다르다. 쿠키가 포트별로 갈리기 때문이다.
    한쪽에서 로그인했는데 다른 쪽이 로그아웃 상태로 보이면 정상이다.

5-3. 두 명 이상을 흉내내려면

  ★ 같은 계정으로 두 곳에서 접속하면 먼저 있던 쪽이 끊긴다 (Q-06, 계정당 소켓 1개).
    그래서 **서로 다른 계정 + 서로 다른 브라우저 프로파일**이 필요하다.

    사람 A  일반 창 (Chrome)
    사람 B  ★ 시크릿 창 또는 다른 브라우저 (Edge, Firefox)
    사람 C  또 다른 브라우저

  같은 브라우저의 일반 탭 두 개는 쿠키를 공유하므로 같은 계정이 되어 서로를 끊는다.

5-4. 확인 항목 4개 — "정상이면 무엇이 보이는가" 포함

  (1) 회원가입 → 로그인 → 방 생성
      절차: 5173 접속 → 회원가입 탭 → test1 / 철수 / 1234 → 방 제목 "테스트 방" → 만들기
      정상
        · 가입 직후 바로 로그인 상태 (다시 로그인하지 않는다)
        · 주소창이 /r/…(16글자 방 ID)로 바뀐다
        · "1 / 10명 · 접속 1명 · LOBBY"
        · 참가자 목록 "1  철수  [방장] [나]"  ★ 닉네임에 색이 들어가 있어야 한다
      추가
        · F5 새로고침 → 로그인 유지 + 같은 방 복귀
        · TEST1(대문자)로 로그인 → 된다 (아이디는 대소문자 무시)
        · 닉네임 철수로 다른 아이디 가입 → "이미 사용 중인 닉네임입니다"
        · 비밀번호 123(3자) → "비밀번호는 4자 이상이어야 합니다"

  (2) 초대 링크 복사 버튼
      절차: 방 안 "초대 링크" 칸의 복사 버튼 → 아무 입력란에 Ctrl+V
      정상
        · 버튼이 잠시 "복사됨" 으로 바뀐다
        · 붙여넣은 값이 http://localhost:5173/r/<방ID>
        · ★ 지금 접속한 주소를 기준으로 만들어진다. 3000으로 접속했다면 3000이 나온다
      이어서: 시크릿 창에서 그 링크를 열고 test2 / 영희로 가입
        · 로그인 화면에 "로그인하면 초대받은 방으로 바로 들어갑니다" 안내
        · 가입하면 자동으로 그 방에 들어간다
        · 원래 창에 "2  영희" 즉시 추가, "2 / 10명"
        · 채팅에 "영희 님이 입장했습니다." 시스템 메시지

  (3) ★★ 한글 IME 조합 중 Enter — 가장 중요. 봇으로 검증 불가
      절차
        1. 채팅 입력창 클릭 → 한/영 키로 한글 모드
        2. "훈민정음" 을 친다. 마지막 "음" 이 아직 조합 중인 상태
        3. Enter 를 한 번 누른다
        4. Enter 를 한 번 더 누른다
      정상
        · 3번의 Enter 는 조합을 확정만 하고 **아무것도 전송하지 않는다.**
          채팅 로그에 새 줄이 생기지 않는다
        · 4번의 Enter 에서 "훈민정음" 전체가 **한 번** 전송된다
        · ★ "훈민정" 이 나타나거나 "훈민정음" 이 두 번 나타나면 버그다
      같이 확인
        · 전송 후 입력창에 커서가 남아 바로 다음 글자를 칠 수 있다
          (매번 클릭해야 하면 버그 — guide 14·42절)
        · 100자를 넘겨 입력할 수 없다
        · 영문 모드에서는 Enter 한 번에 바로 전송된다

  (4) 휴대폰(LTE) 접속과 좁은 화면
      절차
        1. 4번 창에서 npm run build → npm run dev:tunnel
           (터널은 3000번을 공개하므로 클라이언트가 빌드되어 있어야 한다)
        2. 출력된 https 주소를 휴대폰으로 연다. ★ Wi-Fi 끄고 LTE 로
        3. 새 계정(test3 / 민수)으로 가입해 초대 링크로 입장
      정상
        · https 로 열리고 경고가 없다
        · 참가자 목록이 세로로 쌓이고 닉네임·배지가 깨지지 않는다
        · 채팅 로그 높이가 화면을 넘지 않는다
        · 하단 정보(오프셋/RTT)가 세로로 정렬된다
        · PC 창에도 "민수" 가 즉시 나타나고 채팅이 양방향으로 즉시 오간다
      모바일 키보드
        · 키보드가 올라와도 채팅 로그와 전송 버튼이 가려지지 않는다
        · 전송 후 키보드가 닫히지 않는다
      ★ 접속 종료 표시도 함께
        · 휴대폰 탭을 닫으면 PC의 "접속 N명"(활성 인원)은 **즉시** 줄어든다
        · 반면 "민수" 옆 **[접속 종료] 배지는 약 5초 뒤에** 나타난다
          ★ 즉시 나타나면 새로고침마다 깜빡이므로 5초 유예를 둔 것이다 (Q-15)
        · 방장 화면에 "민수" 옆 [내보내기] 버튼이 생긴다

5-5. 확인이 끝난 뒤 정리

    # 터미널을 각각 Ctrl+C (4번 터널 → 3번 클라이언트 → 2번 서버)

    # 테스트 계정·방·세션 삭제 (시드 문제 53개는 남는다)
    docker exec quiz-web-db psql -U quiz -d quizweb -c "DELETE FROM sessions; DELETE FROM rooms; DELETE FROM accounts;"

    # 확인 — accounts=0 / rooms=0 / questions=53
    docker exec quiz-web-db psql -U quiz -d quizweb -t -c "SELECT 'accounts='||count(*) FROM accounts; SELECT 'rooms='||count(*) FROM rooms; SELECT 'questions='||count(*) FROM questions;"

    # DB 는 켜 둬도 무방. 끄려면
    npm run db:down

  ★ 방을 만든 뒤 서버를 Ctrl+C 가 아닌 방법으로 죽였다면 DB에 열린 방이 남는다.
    다음 기동 시 부팅 정리 절차가 자동으로 닫으므로 신경 쓰지 않아도 된다.
    2번 창에 "이전 실행의 잔여 정리: 방 N개 닫음" 이 보이면 그것이 동작한 것이다.
