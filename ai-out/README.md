# ai-out — 라운드별 설계·조사 기록

이 폴더는 프로젝트 진행 과정에서 라운드 단위로 작성된 **시점별 기록(append-only)** 이다.

## 읽는 사람이 가장 먼저 알아야 할 것

> **현재 유효한 규칙과 상태의 정본(正本)은 `docs/` 이다.**
> **`ai-out/` 과 `docs/` 의 내용이 충돌하면 언제나 `docs/` 가 우선한다.**

`ai-out/`의 파일은 "그 시점에 무엇을 조사했고, 어떤 선택지가 있었고, 왜 그렇게 결정했는가"를
남기기 위한 것이다. 결정이 나중에 뒤집히더라도 과거 파일은 수정하지 않는다.
정정이 필요하면 다음 라운드 파일에서 정정한다.

따라서 `ai-out/`의 오래된 문서에는 **현재는 유효하지 않은 서술이 그대로 남아 있다.**
현재 규칙을 알고 싶다면 `docs/`를 봐야 한다.

## 규칙

- 파일명은 `R001.txt`, `R002.txt`, ... 3자리 순번이며 라운드마다 새 파일을 만든다.
- 작성된 파일은 **수정하지 않는다.** append-only.
- 인코딩은 UTF-8, 개행은 저장소 정책(LF)을 따른다.
- 각 파일 맨 앞에 ROUND / DATE / TASK / STATUS 헤더가 있다.

## 라운드 색인

| 파일 | 주요 내용 |
|------|-----------|
| R001.txt | guide.md 전문 분석, 요구사항 인벤토리 약 160건, 결정 필요 항목 Q-01~Q-35, 기술 스택 검증, 무료 티어 조사, 문서 체계·개발 계획 제안 |
| R002.txt | 배포/DB 재조사(유료 최저 티어 포함), OpenTDB 실측 파일럿(전량 수확 4,500건·생존율 분석), 가공 파이프라인 설계, 문제 데이터 구조, 정답 정규화·힌트·마스킹 명세, Q-36~Q-46 |
| R003.txt | 저장소 초기화, 배포/DB 최종 확정(Render Free + Neon Free 권장), 게임 상태 머신(상태 5종·전이 20종·동시 발생 11케이스·타이머), Socket 이벤트 프로토콜, DB 스키마 초안 + guide 40절 통계 역검증, Q-47~Q-52 |

## 관련 문서

- `guide.md` — 최초 요구사항 원본. **수정하지 않고 원형을 보존한다.**
  단 이후 라운드에서 개정된 규칙이 있으므로, guide.md 단독으로 현재 규칙을 판단하면 안 된다.
- `docs/` — 현재 유효한 규칙과 구현 상태의 정본. (Phase 0에서 생성 예정)
