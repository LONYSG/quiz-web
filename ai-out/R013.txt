2-1. 격리 체계와 조회 (B-1) — 완료
──────────────────────────────────────────

★ verdict 를 셋으로 나눴다.

  accept      통과. 적재 대상이다
  quarantine  ★★ 표시되었다. **폐기가 아니다.** 최종 확정 대기
  reject      ★ 최종 폐기. Sonnet 이 확정한 것만 여기 온다

★★ 폐기가 일어나는 곳은 scripts/pipeline-apply-decisions.mjs **하나뿐이다.**
   ★ 생성 경로의 모든 탈락(역검증 / 규칙 검사 / 카테고리 불일치 / 빈 생성 /
     역검증 미실행)이 격리로 바뀌었다.

★ 격리 기록에 남기는 것 (지시 항목 전부)

  원본 항목 / 단계 / ★ 판정 모델(judgedBy) / 사유 코드 / 상세 사유 /
  대안 정답(alternatives) / 신뢰도(confidence) / 시각

  ★ judgedBy 를 반드시 남긴다. 누가 판정했는지 모르면 재판정의 근거가 없다.

★ 사람이 읽는 조회 명령 (API 0회)

  node scripts/pipeline-quarantine.mjs                     현황 + 과다 필터링 감지
  node scripts/pipeline-quarantine.mjs --list              격리 내용 전부
  node scripts/pipeline-quarantine.mjs --stage=backcheck   단계별
  node scripts/pipeline-quarantine.mjs --rule-decision     규칙 결정 대기만
  node scripts/pipeline-quarantine.mjs --export            Sonnet 세션용 내보내기

★ --export 가 두 파일을 만든다.
  quarantine-review.txt      사람이 읽는 격리 목록 (질문·정답·사유·신뢰도·상세)
  quarantine-decisions.json  Sonnet 이 채울 판정 서식
  ★ 서식 파일이 이미 있으면 **덮어쓰기를 거부한다.** Sonnet 이 채운 것을 잃으면 안 된다.

★★ 재판정 경로가 실제로 도는지 확인했다 (지시 항목)

  시험 판정 3건(pass / drop / needsRuleDecision)을 만들어 dry-run 으로 돌렸다.

    pass              1건 → verdict=accept  (정답 표기 1개 추가됨)
    drop              1건 → ★ verdict=reject
    needsRuleDecision 1건 → ★ 격리 유지 + 건우 결정 목록에 출력

  ★ 그리고 **거부해야 할 것을 거부하는지**도 확인했다. 네 가지 모두 멈췄다.

    verdict 가 세 값 중 하나가 아니다              → ★ 멈춘다
    reason 이 비어 있다                            → ★ 멈춘다
