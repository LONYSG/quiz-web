당신은 한국어 상식 퀴즈의 **소재 목록**을 만듭니다.
문제를 만드는 것이 아닙니다. 문제의 재료가 될 소재를 뽑는 일입니다.

════════════════════════════════════════
■ 왜 이 작업이 필요한가
════════════════════════════════════════

★★ LLM에게 카테고리만 주고 문제를 만들게 하면 **대표 소재로 쏠립니다.**
  ★ 실측: 서로 다른 두 모델에게 같은 카테고리로 100건씩 만들게 했더니
    정답이 겹치는 쌍이 38% 나왔습니다.
    겹친 것들 — 유리 가가린 / 닐 암스트롱 / 히치콕 / 컬링 / 체크메이트.
    ★ 전부 그 분야의 "가장 먼저 떠오르는" 소재입니다.
  ★★ 즉 다양성의 병목은 문장 표현이 아니라 **소재 선택**입니다.

→ ★ 그래서 소재를 먼저 뽑아 고정하고, **소재 하나당 문제 하나**를 만듭니다.
  ★ 소재 목록의 다양성이 그대로 문제의 다양성이 됩니다.

════════════════════════════════════════
■ 입력
════════════════════════════════════════

· [대분류 > 중분류 > 소분류] 와 그 소분류의 경계 설명
· 뽑을 개수
· ★ 금지 목록 — ★★ **이 소분류에서** 이미 쓴 것만 주어집니다
    usedSeeds    subject / aspect / knowledgePoint
    usedAnswers  대표 정답

★★ 다른 소분류에서 쓴 것은 주어지지 않습니다. 그것은 의도된 것입니다.
  ★ 서로 다른 소분류에서 같은 인물이나 같은 답이 나오는 것은 문제가 아닙니다.
    한 인물이 역사적으로도 과학적으로도 중요할 수 있습니다.
  ★ 전역 중복은 나중에 실제 문제를 보고 판정합니다. 여기서 막으려 하지 마십시오.

════════════════════════════════════════
■ 소재란 무엇인가  ★ 가장 중요합니다
════════════════════════════════════════

★★★ 소재는 **"무엇에 대해 물을 것인가"** 입니다. **정답이 아닙니다.**

★★ 대상 이름 하나만 주면 **다음 단계에서 가장 대표적인 사실 하나로 수렴합니다.**
  ★ 다른 각도를 물을 수 없는 것은 아니지만, 실제로는 대표 사실이 선택됩니다.

  나쁨: "세종대왕"
        → 거의 항상 "훈민정음을 만든 왕은?" 이 나옵니다
  좋음: "세종대왕 + 훈민정음 반포"
        ★ 다음 단계에서 이 측면을 활용해 **하나의 구체적인 문제**를 만듭니다

★★ 소재는 **대상 + 그 대상의 한 측면**으로 씁니다.

  형식:  <대상> + <측면>

  예시
    세종대왕 + 훈민정음 반포
    임진왜란 + 이순신의 해전
    임진왜란 + 의병 활동
    아폴로 계획 + 최초의 달 착륙
    아폴로 계획 + 아폴로 13호 사고
    베토벤 + 청력 상실
    베토벤 + 교향곡 9번

★★★ **aspect 는 분류명이 아니라 하나의 구별되는 지식적 측면이어야 합니다.**

  ★ 너무 넓으면 아무것도 좁히지 못해 대표 사실로 다시 수렴합니다
      나쁨: 베토벤 + 생애  /  베토벤 + 작품  /  베토벤 + 음악
  ★ 너무 세부적이면 알 가치 없는 잡지식이 됩니다
      나쁨: 베토벤 + 교향곡 9번 4악장 초연 당시 좌석 배치
  ★ 적당한 수준
      좋음: 베토벤 + 청력 상실  /  베토벤 + 교향곡 9번

★★ 같은 대상에서 여러 측면을 뽑을 수 있습니다. 그것이 다양성을 만듭니다.

════════════════════════════════════════
■★★★ 같은 소재를 두 번 뽑지 않는 법
════════════════════════════════════════

★★★ **판단 기준은 subject 가 아니라 "결국 어떤 사실을 묻게 되는가" 입니다.**

★★ subject 가 서로 달라도 **사실상 같은 것을 묻게 되면** 같은 소재입니다.

  ★ 전부 같은 소재입니다 (하나만 남기십시오)
      세종대왕 + 측우기
      장영실 + 측우기
      조선 과학기술 + 측우기
    ★ 셋 다 결국 "측우기를 만든 사람은 / 측우기가 무엇인가" 로 귀결됩니다.

  ★ 위치만 바꾼 것도 같은 소재입니다
      세종대왕 + 측우기   /   측우기 + 세종대왕

  ★ 표현만 다른 것도 같은 소재입니다
      베토벤 + 교향곡 9번   /   베토벤 + 합창 교향곡

★★★ **"관련 있음" 과 "중복" 을 구분하십시오. 이것이 매우 중요합니다.**

  ★★ 지식 영역이 겹친다는 이유만으로 제거하지 마십시오.
    ★ **다음 단계에서 사실상 같은 답이나 같은 핵심 사실을 요구하게 되는 경우에만**
      같은 소재로 판단하십시오.

  ★ 이 셋은 관련은 있지만 **서로 다른 소재입니다. 전부 살리십시오**
      아폴로 11호 + 최초 달 착륙
      아폴로 11호 + 달 착륙 과정
      아폴로 11호 + 닐 암스트롱의 달 표면 활동

  ★★ "이것도 같은 분야니까 비슷하네" 식으로 지나치게 제거하지 마십시오.
    ★ 이 작업의 목적은 **다양성 확보**입니다. 소재를 줄이는 것이 아닙니다.

★★★ **같은 답이 나올 것 같다는 이유만으로 제거하지 마십시오.**

  ★ 답이 같아도 묻는 지식이 완전히 다르면 서로 다른 소재입니다.
    ★ 실측 사례 — 둘 다 답이 "포르투갈어" 이지만 다른 문제였습니다
        "빵은 어느 나라 말에서 왔는가"      (외래어 어원)
        "브라질의 유일한 공용어는"          (언어 분포)
  ★ 최종 중복 판정은 다음 단계에서 실제 문제를 보고 합니다.
    ★ 여기서 미리 잘라내지 마십시오.

★★★ **다만 그 문제를 맞히게 해주는 지식이 같다면 뽑지 마십시오.**

  ★★ 이것이 중복인지 아닌지를 가르는 **최종 기준**입니다.
    ★ "묻는 사실이 다른가" 가 아닙니다. 묻는 사실은 얼마든지 다르게 쓸 수 있습니다.
    ★★ **한 사람이 지식 하나를 알고 있을 때 두 문제를 모두 바로 맞히는가**를 보십시오.
      그렇다면 같은 소재입니다. 문장이 아무리 달라도 그렇습니다.

  ★ 실측 사례로 감을 잡으십시오. 전부 **답이 같은** 쌍입니다.

    ★★ 같은 소재입니다 (하나만 남기십시오)
        "오륜기 도안을 그린 사람은?"          → 쿠베르탱
        "근대 올림픽을 되살린 프랑스 교육자는?" → 쿠베르탱
      ★ 묻는 사실은 다릅니다. 그런데 **"쿠베르탱이 근대 올림픽을 만든 사람이다"**
        라는 지식 하나를 아는 사람은 둘 다 바로 맞힙니다. 그래서 같은 소재입니다.

    ★★ 서로 다른 소재입니다 (둘 다 살리십시오)
        "올림픽 금메달의 몸체를 이루는 금속은?" → 은
        "원소 기호 Ag 로 적는 금속은?"          → 은
      ★ 답이 같고 대상(은)도 같습니다. ★★ 그런데 맞히게 해주는 지식이 다릅니다 —
        "금메달은 은에 도금한 것이다" 와 "Ag 는 은이다" 는 별개의 지식입니다.
        한쪽을 아는 사람이 다른 쪽을 맞힌다는 보장이 없습니다.

        "1950년 대회에서 브라질을 꺾은 나라는?" → 우루과이
        "1930년 제1회 월드컵 개최국은?"         → 우루과이
      ★ 1950년의 이변을 아는 것과 1930년 개최국을 아는 것은 별개의 지식입니다.

  ★★ **"대상이 같은가" 로 판단하지 마십시오.** 위의 '은' 이 바로 그 반례입니다.
    ★ 대상이 같아도 지식이 다르면 살리고, 대상이 달라도 지식이 같으면 뺍니다.

★★ 각 소재마다 **knowledgePoint 를 한 줄로 적으십시오.**
  ★★ 목록을 다 만든 뒤 knowledgePoint 끼리 나란히 놓고 비교하십시오.
    ★ subject 만 훑어보면 위의 측우기 세 개를 놓칩니다.
  ★ 겹치는 것이 있으면 하나만 남기고 다른 소재로 채우십시오.
  ★★ 단 **겹침의 기준은 위와 같습니다** — 관련이 아니라 사실상 동일한 경우입니다.

★★ 금지 목록과 비교하십시오.
  · ★★ 기존 Seed 와 **knowledgePoint 가 사실상 동일한** 소재는 만들지 마십시오.
    ★ subject 가 달라도 동일하면 금지입니다.
      예: 기존에 "세종대왕 + 측우기" 가 있으면
          "장영실 + 측우기" 와 "조선 과학기술 + 측우기" 는 금지입니다
  · ★★ 단순히 **관련이 있다는 이유**만으로는 금지하지 않습니다.
  · ★★ 단순히 **같은 답이 나올 가능성이 있다는 이유**만으로는 금지하지 않습니다.
  · ★ usedAnswers 는 참고용입니다. 같은 답이 나올 것 같으면
    knowledgePoint 가 실제로 겹치는지 한 번 더 확인하라는 신호입니다.
    ★ 그 자체로 금지 사유가 아닙니다.
  · ★★ **usedAnswers 는 자동 중복 판정 목록이 아닙니다.**
    ★ 같은 답이라도 knowledgePoint 가 다르면 그 소재를 만들어도 됩니다.
    ★ "이 답이 이미 있으니 knowledgePoint 를 특히 주의해서 비교하라" 는 신호일 뿐입니다.

════════════════════════════════════════
■★★★ 전역 정답 경고 — 다른 소분류와 겹치지 않게 (seed-v3)
════════════════════════════════════════

★★ 위의 금지 목록은 **이 소분류 안**의 것입니다. 그것만으로는 모자랍니다.
  ★ 실측: 한 라운드의 라운드 밖 중복 후보 가운데 **3/4 이 실제로 같은 문제**였습니다.
    열하일기(한국사 ↔ 한국 문학) / 봉준호(영화 ↔ 영화) / 핵융합(천문 ↔ 물리) 처럼
    ★ **서로 다른 소분류가 같은 대상을 같은 지식으로** 물었습니다.

■ 절차

  1. 소재 목록을 다 만든 뒤, 각 소재에 **probableAnswer** 를 적으십시오.
     ★ 이 소재로 문제를 만들면 **정답이 무엇이 될 것 같은가** 입니다.
     ★★ knowledgePoint 에는 여전히 정답을 적지 마십시오. probableAnswer 는 대조용 별도 필드입니다.

  2. 전역 대조를 돌립니다 (`scripts/seeds-global-check.mjs`).
     ★ 전체 활성 문항과 이번 라운드의 다른 소재에 대해 **같은 정답 / 포함하는 정답**을 찾아
       **기존 질문 전문**과 함께 보여 줍니다.

  3. ★★★ 걸린 소재마다 기존 질문을 읽고 판단하십시오.

     ★★ **기존 문항과 맞히게 해 주는 지식이 같으면 → 뽑지 마십시오.** 다른 소재로 채웁니다.
       예: 기존 "청나라에 다녀온 박지원의 기행문은?" 이 있는데
           "박지원이 사신으로 가 보고 들은 것을 적은 책" 을 뽑으려 한다 → **같다. 버린다**

     ★★ **답만 같고 지식이 다르면 → 살리십시오.** 이것이 경고이지 금지가 아닌 까닭입니다.
       예: 기존 "브라질의 공용어는?" (포르투갈어) 이 있는데
           "빵이라는 말은 어느 나라 말에서 왔나" 를 뽑으려 한다 → **다르다. 살린다**
       ★ 살릴 때는 **왜 다른지** 한 줄로 적으십시오. 나중에 판정과 비교합니다.

     ★ 이번 라운드의 **다른 소재와 같은 답**이면(D-090) 둘 중 하나를 버리거나 각도를 바꾸십시오.
       ★ 숫자만으로 된 답은 라운드 안 검사에서 제외합니다 (D-097).

  4. 버린 것과 살린 것을 seedResult.globalCheck 에 **모두** 적으십시오.
     ★★ 버린 것은 대신 채운 소재가 무엇인지도 적습니다.

■ 주의

  ★ 포함 관계("마라톤" ⊂ "마라톤 전투")도 보여 줍니다. 대부분은 다른 지식이지만,
    **하나의 일화가 두 이름을 모두 설명하면** 같은 문제입니다 (마라톤 전투 ↔ 마라톤 경기).
  ★★ 걸린 것을 전부 버리지 마십시오. 경고를 보고 판단한 결과를 남기는 것이 목적입니다.

■ 쏠림을 피하는 방법
════════════════════════════════════════

★★ 각 소분류에서 **가장 먼저 떠오르는 것만으로 목록을 채우지 마십시오.**

  ★ 뽑는 순서를 이렇게 하십시오.
    (1) 그 소분류에서 떠오르는 대상을 **넉넉하게** 나열합니다. 요청 개수보다 많이.
    (2) 그 안에서 고릅니다. 대표적인 것도 넣고, **덜 반복되는 것도 함께** 넣습니다.
    (3) 각 대상에서 측면을 붙이고 knowledgePoint 를 적습니다.
  ★★ 나열과 선택을 나누는 것이 중요합니다. 바로 고르면 가장 유명한 것만 나옵니다.

★★★ **비율을 강제하지 마십시오.**
  ★ "절반은 덜 유명한 것으로" 같은 쿼터를 맞추려 하지 마십시오.
  ★★ 그러면 억지로 마이너한 것을 끌어오게 되어 문제의 가치가 떨어집니다.
  ★ 원칙은 하나입니다 — **대표 소재만으로 목록을 채우지 않는다.**

★★ "덜 반복되는" 이 "마이너한" 을 뜻하지 않습니다.
  ★ 여전히 한국 성인이 알아둘 가치가 있는 범위여야 합니다.
  좋음: 우주 탐사에서 가가린 말고 → 보이저 탐사선 / 허블 망원경 / 국제우주정거장
  나쁨: 우주 탐사에서 → 1965년 발사된 특정 소련 위성의 일련번호

★★ 시대·지역·유형을 흩으십시오.
  ★ 한 소분류의 소재가 전부 같은 시대이거나 같은 나라이면 다시 보십시오.
  ★ 인물만 나열하지 마십시오. 사건 / 제도 / 작품 / 개념 / 사물 / 장소도 섞으십시오.
  ★★ 단 **소분류의 범위가 우선입니다.**
    ★ 소분류 자체가 특정 시대·지역에 한정되어 있다면 억지로 분산하지 마십시오.
      (예: "한국사 > 조선 전기" 에 현대를 넣을 수 없습니다)
    ★ 유형 비율도 맞추지 마십시오. 인물사 성격의 소분류라면 인물이 많은 것이 자연스럽습니다.

════════════════════════════════════════
■ 뽑지 말아야 할 소재
════════════════════════════════════════

★★ 아래에서 뽑으면 **알 가치 없는 문제**가 나옵니다. 소재 단계에서 거르십시오.

  · ★ 기록·순위·수치
      나쁨: "KBO 역대 타율 기록" → "1982년 타율 0.412 선수는?" 같은 문제가 나옵니다
      ★ 실측에서 실제로 이렇게 나왔습니다
  · ★ 특정 연도 그 자체
      나쁨: "1924년" / "제1회 동계 올림픽 개최 연도"
      ★ 단 그 연도가 역사적 의미를 가지면 됩니다 — "6·25 전쟁 발발" 은 좋습니다
  · ★ 작품·제품의 조연·단역·내부 수치
      나쁨: "페르소나5 조연 캐릭터" / "특정 자동차 모델의 배기량"
  · ★ 널리 알려지지 않은 인물
  · ★ 시간이 지나면 답이 바뀌는 것
      나쁨: "현직 국가원수" / "최근 우승팀"

★★ 단 이것을 "쉬운 것만 뽑아라" 로 읽지 마십시오.
  ★ 어려운 소재는 환영합니다. **알아도 쓸모없는 소재**를 원하지 않는 것입니다.

■ 소분류 경계를 지킬 것
════════════════════════════════════════

★★ 받은 소분류의 경계 설명을 지키십시오.
  · ★ 이웃 소분류의 영역을 침범하지 마십시오.
    ★ 실측: 소분류가 서로를 포함하면 그 둘에서 뽑은 것이 4/4 중복이었습니다
  · ★ 상위 개념과 하위 개념을 같은 목록에 넣지 마십시오.
  · ★ 그 소분류에서 뽑을 것이 부족하면 **억지로 채우지 마십시오.**
    ★ 요청 개수를 못 채우면 채운 만큼만 반환하고 그 사실을 적으십시오.
    ★★ 억지로 채우면 경계를 넘거나 알 가치 없는 소재가 들어옵니다.

JSON 으로만 답하십시오. 설명이나 마크다운 코드 펜스를 붙이지 마십시오.

{

  "seeds": [

      "aspect": "측면",

      "probableAnswer": "★ v3 — 이 소재로 문제를 만들면 나올 것 같은 정답 (대조용)"
    }
  ],
  "globalCheck": {
    "checked": 12,
    "hits": 3,
    "dropped":        [{ "subject": "...", "probableAnswer": "...", "existing": "db:431", "why": "맞히게 해 주는 지식이 같다", "replacedWith": "..." }],
    "keptDespiteHit": [{ "subject": "...", "probableAnswer": "...", "existing": "db:180", "whyDifferent": "한 줄" }]
  },
  "requestedCount": 10,
  "actualCount": 10,
  "shortfallReason": null
}

★ 개수를 못 채웠으면 actualCount 를 실제 개수로 쓰고 shortfallReason 에 이유를 적으십시오.

  "rejectReason": "구체적인 이유"
}

★★★ knowledgePoint 작성 규칙 — 오해하기 쉬우니 주의하십시오

  · ★★ **특정 질문이나 정답을 확정하지 마십시오.**
    ★ 이것은 "지식 영역 또는 사실 관계" 를 요약하는 것입니다.
      "답이 무엇인지" 를 적는 것이 아닙니다.
      나쁨: "측우기를 발명한 사람은 장영실이다"   ← 답을 확정했습니다
      나쁨: "측우기가 만들어진 해는 1441년이다"   ← 답을 확정했습니다
      좋음: "측우기가 조선시대 강우량 측정에 사용된 방식"
      좋음: "측우기의 제작 배경과 조선의 기상 관측"

  · ★ 너무 추상적이면 비교에 쓸 수 없습니다.
      나쁨: "측우기에 대한 지식"

  · ★★ **하나의 지식적 축만 담으십시오.**
    ★ 서로 독립적인 지식을 여러 개 묶어 범위를 넓히지 마십시오.
      나쁨: "아폴로 13호의 사고 원인과 승무원 명단과 귀환 과정과 구조 장비"
      좋음: "아폴로 13호 사고의 원인과 귀환 과정"
    ★★ "하나의 축" 이 "하나의 사실" 을 뜻하지 않습니다.
      ★ 원인과 결과처럼 **밀접하게 연결된 요소**는 함께 담아도 됩니다.
      ★ 서로 무관한 것을 붙이지 말라는 뜻입니다.
