# 지시서 — 재료 (v0.3 · 2026-11-13 · 시범 — 005 를 만든 쪽의 제안 5개 + gpt 036 의 보완 3개 반영)

카드 다시 쓰기의 **앞 단계**다. 너(max 쪽 · Opus)는 문장을 쓰지 않는다. 마지막 문장은 gpt 가 쓴다. 네 일은 gpt 가 **검색 없이** 좋은 카드를 쓸 수 있게 **확인된 재료**를 모아 주는 것이다. 곁들여 난이도 · 카테고리 · 알가치 · 중복을 한 번에 본다(같은 카드를 두 번 읽지 않는다).

- 입력: `보낼것/카드-NNN.txt`(원문 100장 · `메모:` 줄에 실전 기록) · `보낼것/같은정답-NNN.txt`(정답이 같은 다른 문항의 지금 질문 · 힌트)
- 기준: `지시서-카드.md` §0 · §1(좋은 카드가 무엇인가 — gpt 가 이 기준으로 쓴다. 너는 그 기준에 맞는 **재료**를 고른다)
- 출력: `보낼것/재료-NNN.json`

## 1. 카드마다 하는 일
1. **원문 사실 확인.** 세 칸에 든 사실을 낱개로 나눠 적고 하나씩 표시한다.
   - 출처를 **열어서** 확인할 것: 연도 · 수 · "처음 · 가장 · 유일" · 누가 했다 · 이름의 유래 · 인과("~해서 ~가 됐다") · 조금이라도 의심스러운 것.
   - 열지 않아도 되는 것: 누구나 아는 정의 · 줄거리(예: "축구는 11명") → `check: "상식"`.
   - 표시: `맞음`(출처가 말한 그대로) / `틀림`(→ `fixed` 에 출처가 말한 만큼만 고친 사실) / `못 엶`(출처를 못 찾음 — gpt 는 이 사실을 쓰지 않는다).
   - ★ 출처보다 한 걸음 더 나가지 않는다(V055 · V056 에서 되풀이된 실수): 출처에 없는 "대표" · "가장" · 동기 · 범위 한정을 붙이지 않는다. 해석이 갈리면 `fixed` 를 "보통 ~로 해석된다" 꼴로.
2. **대표 사실 제안**(`core`) — 이 정답을 들으면 "아, 그거!" 하게 되는 사실 한 줄. 원문 질문에 이미 있으면 `"원문 질문 그대로"`. 원문 세 칸 어디에도 없으면 출처를 열어 새 사실로 넣는다(3으로).
3. **모자란 카드에 이야깃거리**(`extra`) — 세 칸이 같은 말을 되풀이하거나, 해설이 정의를 다시 읽는 수준이면 출처 있는 사실을 1~2개 보탠다(일화 · 유래 · 뜻밖의 연결). **정답이 주인공**인 것만. 넉넉한 카드에는 넣지 않는다.
   - ★ 다른 문항의 정답이 될 만한 것을 이야깃거리로 쓰지 않는다(예: 체스 '킹' 카드에 캐슬링 이야기 — 캐슬링이 다른 카드의 정답이다). `같은정답` 파일과 이 묶음 안의 정답들을 본다.
4. **같은 정답 문항과 가르기**(`angle`) — `같은정답-NNN.txt` 에 이 id 가 있으면: 두 문항이 **같은 문제**(같은 사실을 묻는다)인지 **다른 각도**인지 판단하고, 다른 각도면 "이 카드는 ○○ 쪽, #다른id 는 △△ 쪽" 한 줄. 대표 사실이 하나뿐이라 둘 다 그것을 물을 수밖에 없으면 `같은 문제` — 하나를 끌 후보로 올린다(끄는 것은 기획자가 정한다).
5. **곁들임**(`meta` — 문장 재료와 섞지 않는다)
   - `difficulty`: `{ "now": 3, "propose": 2, "why": "…" }` — 기준은 **"20~40대 친구 4명이 있는 방에서 30초 안에 누군가 맞힐 확률"**: 1 = 거의 항상(90%↑) · 2 = 대개(70%쯤) · 3 = 반반 · 4 = 가끔(30%쯤) · 5 = 드물게(10%↓). 대표 사실을 질문에 넣었을 때를 기준으로. `메모:` 의 실전 기록(몇 번 나와 몇 번 못 맞힘)이 있으면 그것이 먼저다. 지금 값과 같으면 `propose` 를 같은 수로, `why` 는 비워도 된다. 너는 사람보다 훨씬 많이 안다 — 네가 쉽다고 느끼는 것보다 한 칸 어렵게 본다.
   - `worth_low`: 알아도 그만인 문항이면 한 줄 사유, 아니면 `null`. **자르지 않는다 — 표시만.**
   - `category_off`: 원문 분야가 명백히 어긋나 보일 때만 한 줄(입력에 분야가 없으니 대개 `null`).
6. **원문이 통째로 틀렸거나 정답이 둘 이상 가능하면** `note` 에 적고 `hold: true`(gpt 가 쓰지 않고 기획자 · 검수가 먼저 본다).

### 덧붙임 (v0.1)
- **출처끼리 다를 때**(53명 / 57명 · 1846 / 1847년): `check: "엇갈림"` — `fixed` 에 "출처 A 는 ○, 출처 B 는 △" 를 적고 url 둘. gpt 는 **이 수를 쓰지 않는다**("약 ~" 로 뭉개지 않는다 — 두 수가 집계 대상 · 사건이 다른 것일 수 있다). 그 수가 질문의 핵심이면 `hold: true`.
- **사실 하나에서 낱말 하나만 확인이 안 될 때**(○○년 **1월** 의 '1월'): fact 를 둘로 쪼갠다 — 확인된 쪽 `맞음`, 나머지 `못 엶`.
- **표 칸 · 기사 제목으로 확인한 것**: quote 에 그 칸 · 제목을 그대로 넣고 앞에 `[표]` / `[제목]`.
- **민간 어원 · 설화**: `check: "맞음"` 으로 두되 text 를 "~라는 이야기가 전한다" 꼴로 적는다(사실이 아니라 '그런 이야기가 있다'가 확인된 것).
- **`core_from`** 칸을 둔다: 대표 사실이 지금 어디에 있나 — `"질문"` / `"힌트"` / `"해설"` / `"새로"`. "힌트 → 질문으로 올리기"가 가장 흔한 처방이다.
- **같은 문제 판정의 기준**: 원문이 아니라 **두 카드 모두 대표 사실을 질문에 올렸을 때** 같은 질문이 되는가.
- **`meta.hint_clash`**: 다른 문항과 힌트 문장이 겹치면 `"#id"`(같은 판에 나오면 힌트가 답을 준다).
- **질문의 핵심 사실이 `못 엶` 이면 `hold: true`**(재료가 없는 카드를 gpt 가 억지로 쓰지 않게).

- **식별자**(v0.2): 모든 fact 에 `fact_id`(`"<id>-f<번호>"`) · 모든 extra 에 `extra_id`(`"<id>-e<번호>"`) · 파일 머리에 `version`. 판정 파일은 이 식별자로 가리킨다. 재료를 고칠 때 번호를 다시 매기지 않는다(지운 것은 빈 번호로 둔다).
- **정답 변형**(v0.2): item 에 `variants`(DB 의 정답 변형 전부 — 내보내기가 붙인다). 힌트 재료를 고를 때 변형 · 다른 이름이 든 사실에는 `text` 끝에 `(다른 이름 포함)`.

### V058 이 재료-005 에서 짚은 것 (v0.3 — 다음 재료부터)
- text 가 quote 의 **서수 · 최상급**("첫 · 가장 · 대표")을 더하거나, quote 의 **완화**("~라고 할 수 있다")를 지우지 않는다. (베스파 "첫 스쿠터 모델" — 출처에 '첫' 없음 · 우정총국 "최초의 우체국이라고 할 수 있다" → 단정)
- quote 는 text 의 **주어 · 대상을 말하는 그 문장**이어야 한다. 같은 페이지의 다른 문장을 붙이지 않는다. 사실 하나에 이름이 셋이면 셋 다 그 페이지에 있어야 한다.
- 출처가 "주장한다 / 밝혔다"로 쓴 것을 "연구 결과"로 올리지 않는다 — "~가 밝혔다" 꼴 그대로.
- 기관지 · 신문 · 사전 **이름**은 그 페이지가 그렇게 말할 때만 적는다.
- 다 쓴 뒤 `맞음` 을 무작위 30개 뽑아 url 을 다시 열고 위 네 가지를 스스로 대조한다(V058 표본: 맞음 40 중 fix 4).

### V059 가 재료-006~017 에서 짚은 것 (2026-11-14 — 다음 재료부터 · 파일의 `version` 은 그대로 `v0.3`)
1,409 판정 중 fix 50 — 전부 "출처보다 한 걸음 더"였다.
- text · fixed 는 quote 의 **한정어**(probably · reportedly · supposedly · may · "이본에 따라" · "공식 역사에 따르면")를 지우지 않는다. (mixed reviews → "혹평" · pioneered → "처음" 금지)
- quote 에 없는 **이유 · 동기 · 시점**("~때문에" · "처음에" · "새벽")을 붙이지 않고, **주어 · 범위**를 바꾸지 않는다(두 사람이 한 일 → 한 사람 · 북미 규칙 → 일반 규칙).
- `fixed` 안에 "(출처에 ~없음)" 같은 **메모 괄호를 넣지 않는다** — 뺀 문장만 적고, 메모는 `note` 에.
- "대표 · 가장 · 처음 · 연도 · 수"가 든 사실은 `상식` 으로 넘기지 않고 연다.
- 서로 다른 문서의 연도 · 이름을 한 사실로 잇지 않는다(5583-f7).

## 2. 출력 — `보낼것/재료-NNN.json`
```json
{ "chunk": "005", "done": true, "version": "v0.2", "items": [
  { "id": 4472, "answer": "칠정산", "hold": false,
    "facts": [
      { "text": "세종 때 만든 역법서", "where": "질문", "check": "맞음", "url": "https://…", "quote": "출처 문장(원문 그대로 · 80자 안)" },
      { "text": "책 이름의 칠정 = 해 · 달 · 다섯 행성", "where": "해설", "check": "상식" },
      { "text": "…", "where": "힌트", "check": "틀림", "fixed": "출처가 말한 만큼만 고친 사실", "url": "…", "quote": "…" }
    ],
    "core": "원문 질문 그대로",
    "extra": [ { "text": "새 사실 한 문장", "url": "…", "quote": "…" } ],
    "angle": null,
    "meta": { "difficulty": { "now": 3, "propose": 4, "why": "…" }, "worth_low": null, "category_off": null },
    "note": "" }
] }
```
- ★ `"done": true` 는 **다 쓰고 자체 검사까지 끝낸 뒤 한 번에** 저장할 때 넣는다(없으면 VERIFY · gpt 가 읽지 않는다).
- 입력의 모든 id 를 순서대로 · 누락 · 중복 없이.
- `url` 은 **실제로 연 페이지**만. `quote` 는 그 페이지의 문장을 옮긴 것(한국어가 아니면 원문 그대로). 기억으로 채우지 않는다.
- 사실은 **한 줄에 하나**. 문장을 다듬지 않는다(다듬는 것은 gpt 의 일) — 군말 없이 사실만.

## 3. 하지 않는 것
- 질문 · 힌트 · 해설 문장을 쓰지 않는다(이 시범 묶음은 꼬인 꼴이라 초안 없이 간다).
- 정답을 바꾸지 않는다. 문항을 끄지 않는다.
