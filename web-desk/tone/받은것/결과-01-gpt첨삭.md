## 전체 검토 결과

이번 조각은 원문과 재작성 결과가 각각 47문항으로 일치하고, ID와 순서도 모두 맞습니다. 재작성 결과는 `rewrite` 39개, `keep` 7개, `discard` 1개(ID 22)입니다.

먼저 결론부터 말하면, 원문의 숫자·연도·고유명사가 재작성 과정에서 바뀐 뚜렷한 사례는 보이지 않습니다. 다만 문장 형태를 바꾸면서 오히려 길어진 문항, 회사·브랜드를 묻는데 장소를 묻는 듯한 마지막 표현, 정답 별칭에 넣기에는 범위가 넓은 표현이 있습니다.

이번 검토는 첨부된 원문과 결과 JSON의 대조입니다. 원문에 적힌 역사·과학적 사실 자체를 외부 자료로 독립 검증한 것은 아닙니다.

## 4. `discard` 판단: 버린 문항과 살릴 문항

이번 결과에서 `discard`는 ID 22 하나뿐입니다.

### ID 22 — discard는 타당하지만, 게임 구성에 따라 선택 가능

- 원문: `사과를 영어로 쓰면?`
- 정답: `Apple`
- 폐기 사유: 기본적인 영어 단어를 묻는 단순 암기 문항이라 남는 것이 없음

지시서의 `empty` 기준에 잘 들어맞습니다. 20\~40대 친구들이 하는 파티 퀴즈라는 점을 고려하면, 정답을 맞혀도 별다른 이야기나 지식이 남지 않는 문항입니다.

다만 등급 1의 쉬운 문제를 워밍업용으로 일부 남기려는 기획이라면 살릴 수도 있습니다. 예를 들면 다음과 같습니다.

> 영어로 '사과'를 뜻하면서, 아이폰을 만드는 회사의 이름이기도 한 단어는 무엇일까요?

이렇게 하면 단순 번역 문제가 아니라 중의적인 단어를 활용한 문제가 됩니다. 다만 힌트가 이미 회사 이름을 알려 주기 때문에 난도는 매우 낮습니다.

제 판단: 현재 지시서의 기준대로라면 `discard`를 유지해도 좋습니다. 다만 쉬운 문항을 의도적으로 남길 계획이라면, 낮은 난도 자체를 폐기 이유로 삼지 않도록 기준을 구분해야 합니다.

### 살릴 수 있는데 버린 문항

이번 조각에서는 ID 22 외에 폐기된 문항이 없으므로, 별도로 살려야 할 폐기 문항은 없습니다.

### 버려야 하는데 살린 문항

질문만 놓고 볼 때 폐기해야 한다고 판단할 문항은 발견하지 못했습니다.

다만 ID 5705, 6302, 4825, 7169처럼 역사적 일화나 특정 연도·인물·사건에 의존하는 문항은 질문의 완성도와 별개로 사실 검증을 거친 뒤 최종 승인하는 것이 좋습니다. 이번 검토에서는 원문과 결과의 일치 여부만 비교했으므로, 사실 검증이 끝났다는 뜻은 아닙니다.

## 5. 지시서 수정 제안

현재 지시서에는 이미 좋은 규칙이 들어 있습니다. 특히 다음 두 문장은 방향이 정확합니다.

- 이미 잘 읽히는 질문은 그대로 두고 어색한 곳만 고치는 것도 올바른 다시 쓰기입니다.
- 정의를 평서문으로 바꾼 뒤 같은 것을 다시 묻지 않습니다.

그런데 이번 결과에서 ID 396과 768처럼 같은 문제가 반복됐습니다. 규칙을 조금 더 구체적으로 바꾸면 좋겠습니다.

### 수정 1 — 1절 '세 가지 꼴 고르기'

현재 23번 문장:

> 짧은 꼴(`short` · 설명 한 문장 + 질문) — 사연 · 변화 · 대조가 있는 문항("원래는 \~였지만 지금은 \~")만 설명문으로 풀고 묻습니다.

다음 문장으로 교체하는 것을 권합니다.

- **짧은 꼴**(`short` · 설명 한 문장 + 질문) — 사연·변화·대조·역사적 배경처럼 설명을 먼저 제시해야 질문이 자연스러워지는 문항에 씁니다. 단순한 정의나 특징 하나를 묻는 문항은 여기에 넣지 않습니다. 정의형 문항은 원칙적으로 `line`을 선택합니다. 설명문을 하나 더 붙여 질문을 두 문장으로 만드는 것이 읽기 편해지는 경우에만 `short`를 사용합니다.

이렇게 하면 ID 396처럼 통신 규약의 정의를 설명한 뒤 다시 통신 규약을 묻는 문항이 `short`로 분류되는 것을 줄일 수 있습니다.

### 수정 2 — 1절의 반복 금지 규칙 강화

현재 25번 문장:

> 정의를 평서문으로 바꾼 뒤 같은 것을 다시 묻지 않습니다. 정보는 그대로인데 길이만 늘어납니다.

다음 문장으로 교체하는 것을 권합니다.

- **정의형 문항은 정의 자체를 질문으로 만듭니다.** `A는 B입니다. B는 무엇일까요?`처럼 같은 정보를 평서문과 질문에서 반복하지 않습니다. 질문 앞에 설명문을 붙였더라도 새로운 단서나 맥락이 추가되지 않았다면 한 문장으로 합칩니다. 예를 들어 `별이 붉게도 푸르게도 보이는 것은 어떤 값이 다르기 때문입니다. 이 값은 무엇일까요?`가 아니라, `별빛이 붉을수록 낮고 푸를수록 높게 나타나는 별의 물리량은 무엇일까요?`처럼 씁니다.

특히 ID 768의 실수를 직접 막는 예시를 넣는 것이 효과적입니다.

### 수정 3 — 3절 마지막 질문에 회사·브랜드·단체 추가

현재 표에는 사람, 장소, 작품, 수 등이 있지만 회사나 브랜드 같은 조직·상호가 빠져 있습니다.

표에 다음 행을 추가하면 됩니다.

\| 회사 · 브랜드 · 단체 | `이 회사의 이름은 무엇일까요?` · `어느 브랜드일까요?` · `이 구단의 이름은 무엇일까요?` |

- 회사·브랜드·구단처럼 이름을 답하는 문항에 `어디일까요?`를 습관적으로 쓰지 않습니다. 장소를 묻는 것이 아니라면 `무엇일까요?`, `어느 회사일까요?`처럼 답의 종류가 분명하게 드러나도록 합니다.

이 규칙은 ID 4301, 3255, 3252, 161, 5703에 직접 적용할 수 있습니다.

### 수정 4 — 6절 aliases 기준에 범위가 다른 표현 예시 추가

현재 74\~75번 문장도 원칙적으로 충분하지만, 실제 결과에서 `강타`, `24초 바이얼레이션`, `폭스바겐 그룹`처럼 비슷해 보이지만 동일하지 않은 표현이 들어갔습니다.

다음 문장을 추가하는 것을 권합니다.

- **비슷한 표현이라고 무조건 `aliases`에 넣지 않습니다.** 정답과 의미·범위가 실질적으로 같은 표현만 허용합니다. 일반적인 상위 개념이나 관련 용어, 규칙 자체와 그 규칙을 어겼을 때의 반칙·위반 명칭, 회사와 그 회사를 포함하는 기업 집단의 이름은 별칭으로 인정하지 않습니다. 예를 들어 `스파이크`의 별칭으로 일반적인 `강타`, `24초 룰`의 별칭으로 `24초 바이얼레이션`, `폭스바겐`의 별칭으로 `폭스바겐 그룹`을 넣지 않습니다.
