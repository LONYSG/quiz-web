# 전체 검토 결과

세 파일을 대조해 확인했어. 원문 47개와 재작성 결과 47개는 ID와 순서가 모두 일치해. 문항 누락이나 추가는 없어.

전체적으로는 지시서의 형식을 잘 따랐지만, 눈에 띄는 문제도 있어. 특히 다음 세 가지가 중요해.

1. 짧게 끝내도 되는 문항을 불필요하게 늘린 사례가 있어. `이것은 무엇일까요?`를 붙이기 위해 이미 완결된 설명을 다시 반복하는 식이야.
2. 원문에 있던 핵심 사실을 질문에서 빼거나 표현을 바꾼 사례가 있어. 특히 질문의 단서가 줄어들면 힌트에 대한 의존도가 커져.
3. discard 판정이 지나치게 엄격한 사례가 있어. 정답 표현에 유사어나 관련 용어가 있다는 이유만으로 폐기할 필요는 없어. 채점 별칭이나 질문의 범위를 조정해서 살릴 수 있는 문항이야.

아래에서는 문항을 실제 게임 화면에 띄운다는 기준으로, 읽는 시간과 정답을 입력하기까지의 흐름도 함께 고려할게.

## 2. 사실·숫자·고유명사 변경 여부

질문에 들어간 원문의 핵심 사실, 숫자, 고유명사가 바뀐 사례는 확인되지 않았어. 47개 모두 ID와 순서가 유지됐고, 재작성된 질문도 원문에 있던 단서를 대체로 그대로 보존했어.

다만 세 가지는 별도로 짚을게.

- ID 4897: “같은 1,848경기에서”를 “같은 1,848경기를 치르는 동안”으로 바꿨어. 의미는 같으므로 숫자나 사실이 바뀐 것은 아니야.
- ID 4612: “지구에서 가장 크다는”을 “지구에서 가장 크다고 알려진”으로 바꿨어. 사실을 바꾼 것은 아니지만, 원문의 단정적 표현을 완화했어. 이 표현을 바꿀 근거가 따로 없다면 원문을 유지하는 편이 좋아.
- ID 6449: 질문의 사실은 그대로지만 해설이 `null`로 출력됐어. 지시서의 규칙대로라면 끝 어미를 고치지 않았으므로 `null`이 맞아. 다만 결과 JSON을 원본에 덮어씌우는 방식으로 처리한다면 해설이 사라질 수 있어. 이 부분은 데이터 병합 규칙을 명확히 해야 해.

그리고 이 검토는 원문과 재작성 결과 사이에 변경이 있었는지를 확인한 것이야. 1857년의 재판 내용이나 1936년 올림픽 관련 일화처럼 원문에 이미 들어 있는 사실 자체가 역사적으로 정확한지는 별도의 사실 검증이 필요해.

### ID 1195 — 소급입법 금지

살리는 편이 좋음

AI가 제시한 사유는 형벌불소급·소급효 금지·죄형법정주의 등 여러 용어가 가능하다는 것이야. 하지만 이 용어들이 모두 같은 범위의 동의어인 것은 아니야.

- 형벌불소급 원칙: 행위 당시 범죄가 아니었던 행위를 나중에 만든 법으로 처벌하지 못한다는 원칙
- 죄형법정주의: 범죄와 형벌은 법률로 정해야 한다는 더 넓은 원칙

원문은 이미 행위 당시 없던 법을 나중에 만들어 과거 행위를 처벌하지 못한다는 내용을 제시하고 있어. 따라서 문항 자체가 성립하지 않는다고 보기는 어려워.

추천 질문:

> 행위 당시에는 범죄가 아니었던 일을 나중에 만든 법률로 거슬러 처벌하지 못하게 하는 원칙이 있습니다. 이를 무엇이라고 할까요?

정답은 기존대로 `소급입법 금지`를 유지하고, 채점 단계에서 `형벌불소급`, `형벌불소급의 원칙`, `소급처벌 금지` 등을 허용 답안으로 등록하는 편이 좋아. `죄형법정주의`는 더 넓은 개념이므로 같은 답으로 무조건 인정하지 않는 것이 적절해.

살리는 편이 좋음

AI는 탄소 배출 계수·배출 계수·탄소 집약도·배출 원단위가 모두 성립할 수 있다고 판단했어.

이 중 일부는 맥락에 따라 비슷하게 쓰이지만, 모두 완전히 같은 개념이라고 볼 수는 없어. 용어가 비슷하다는 이유만으로 폐기할 필요는 없어.

추천 질문:

> 같은 양의 전기를 만들더라도 발전 방식에 따라 배출되는 온실가스의 양은 다릅니다. 전력 1kWh를 생산할 때 배출되는 온실가스의 양을 나타내는 계수를 무엇이라고 할까요?

정답은 `탄소 배출 계수`를 유지하고, 채점 별칭으로 `배출계수` 등을 검토하면 돼. 단, `탄소 집약도`는 사용하는 정의와 단위가 다를 수 있으므로 자동으로 정답 처리하지 않는 게 좋아.

### keep 판정

ID 8017과 8006은 이모지 문항이므로 `keep` 판정이 정확해. 지시서의 예외 규칙을 잘 지켰어.

이번 결과에서 discard로 표시된 두 문항은 모두 살릴 수 있어 보여. 반대로 반드시 discard해야 하는 문항을 잘못 살린 사례는 이번 47개에서는 뚜렷하게 발견하지 못했어. 다만 5515처럼 원문 자체가 복잡하고 특정 일화에 의존하는 문항은 문장 재작성과 별개로 사실 검증을 거쳐야 해.

## 5. 지시서에서 바꿀 부분

전체 지시서를 다시 쓸 필요는 없어. 이번 결과에서 반복된 실수를 막으려면 아래 네 곳만 보완하면 돼.

### 수정 ① 1절 「목표」에 문장 반복 금지 추가

현재 지시서에는 대상을 “이것은 · 이 사람은 · 이 나라는”처럼 소개하라고 되어 있어. AI가 이 규칙을 기계적으로 적용하면서, 원래 자연스러운 질문까지 `이것은 …입니다. 이것은 무엇일까요?`로 바꾼 것으로 보여.

1절의 설명 → 마지막 질문 규칙 아래에 다음 내용을 추가하는 것을 권장해.

- **이미 자연스러운 질문은 억지로 설명문으로 바꾸지 않습니다.** 원문이 한 문장으로 명확하게 설명하고 마지막에 질문하는 구조라면, 문장 구조를 유지한 채 끝 표현만 다듬어도 됩니다.
- `이것은 · 이 사람은 · 이 작품은` 같은 표현은 문맥상 자연스러울 때만 사용합니다. 설명문에서 대상을 이미 소개했다면 마지막 질문에서 같은 대상을 불필요하게 반복하지 않습니다.
- `이것은 전쟁입니다. 이 전쟁은 무엇일까요?`처럼 설명문과 질문이 같은 정보를 되풀이하는 구조는 피합니다. 짧은 꼴은 설명을 한 번만 제시하고 마지막에 질문합니다.

### 수정 ② 1절 「짧은 꼴과 긴 꼴 고르기」 보완

이번 결과는 짧은 꼴과 긴 꼴을 구분하긴 했지만, 짧은 문항을 무조건 `이것은 …입니다`로 바꾸는 경향이 있었어.

짧은 꼴 설명을 다음처럼 바꾸면 좋아.

- **짧은 꼴**(설명 한 문장 + 질문) — 핵심 단서를 한 문장으로 전달하고 바로 물으면 충분한 문항입니다. 원문이 이미 이 구조라면 그대로 살리고, 질문의 끝 표현만 다듬습니다. 설명을 평서문으로 바꾼 뒤 같은 내용을 다시 질문하지 않습니다.
- **긴 꼴**(설명 두세 문장 이상 + 질문) — 단서가 여러 개이거나 배경·사건·특징을 순서대로 풀어야 자연스러운 문항입니다. 문장 수를 늘리는 것이 목적이 아니라, 단서가 쌓이는 흐름을 만드는 것이 목적입니다.

### 수정 ③ 6절 「폐기를 제안하는 문항」의 narrow 기준 수정

이번에 가장 명확하게 드러난 판단 오류야. 정답과 관련된 용어가 여러 개 있다는 것과, 실제로 여러 답이 동등하게 성립한다는 것은 달라.

현재 narrow 설명을 다음으로 교체하는 것을 권장해.

- `narrow` — 질문을 정확히 이해해도 서로 다른 정답이 동등하게 성립하고, 질문의 표현을 조금 고치는 것만으로는 하나의 답으로 좁히기 어려운 경우입니다.
  - 같은 개념을 가리키는 동의어·약칭·다른 표기법이 있는 것은 폐기 사유가 아닙니다. 허용 답안이나 채점 별칭으로 처리합니다.
  - 상위 개념과 하위 개념, 관련 개념이 함께 떠오른다는 이유만으로 폐기하지 않습니다. 질문의 범위를 구체화해 구분할 수 있는지 먼저 검토합니다.
  - 질문을 명확하게 고치고도 서로 다른 답이 여전히 성립할 때만 폐기합니다.

그리고 출력 형식에 `answer_aliases` 필드를 추가하는 게 좋아.

예를 들면:

```
{
  "id": 1195,
  "verdict": "rewrite",
  "form": "short",
  "question": "행위 당시에는 범죄가 아니었던 일을 나중에 만든 법률로 거슬러 처벌하지 못하게 하는 원칙이 있습니다. 이를 무엇이라고 할까요?",
  "answer_aliases": ["형벌불소급", "형벌불소급의 원칙", "소급처벌 금지"]
}
```

이렇게 하면 질문은 하나의 답을 유도하면서도, 실제 채팅 게임에서 표현 차이 때문에 정답을 놓치는 문제를 줄일 수 있어.

### 수정 ④ 7절 「출력」에 null 처리 규칙 추가

이건 문장 품질보다 데이터 처리 측면에서 중요해.

현재 지시서는 해설을 수정하지 않으면 `null`로 출력하게 되어 있어. 그런데 이 JSON이 원본을 갱신하는 전체 데이터인지, 원본에 적용하는 변경사항만 담은 패치인지 명확하지 않아.

다음 내용을 추가해 줘.

- `hint`와 `explanation`의 `null`은 해당 필드를 삭제하거나 비우라는 뜻이 아니라, 원본 내용을 그대로 유지하라는 뜻입니다.
- `verdict: "keep"`인 문항은 원본 질문·정답·힌트·해설을 모두 그대로 유지합니다.
- `verdict: "discard"`인 문항만 최종 배포 대상에서 제외합니다.
- 결과를 원본 데이터와 병합할 때 `null`을 빈 값으로 덮어쓰지 않습니다. 최종 배포용 전체 데이터를 만들 때는 원본에서 유지할 필드까지 복원해야 합니다.

## 추가로 발견한 데이터 품질 문제

ID 2679와 3372가 같은 정답 `독화살개구리`를 공유해.

- 2679는 화려한 색과 독, 사냥 도구에 독을 발랐다는 유래를 묻고,
- 3372는 올챙이를 등에 업어 나무 위 물웅덩이로 옮기는 번식 행동을 묻고 있어.

서로 다른 특징을 다루므로 둘 다 살릴 수 있어. 다만 게임에서 같은 정답이 반복되는 것은 의도된 구성인지 확인하는 편이 좋아. 전체 7,880개를 처리할 때는 중복 정답뿐 아니라 유사한 질문과 힌트도 함께 검사하는 것이 좋겠어.
