# 문항 재구성 — 지시서 (v1.1 · 2026-11-13 · max · gpt 013 의 출력 계약 + 덧붙임 둘 + V053 전수 검수에서 나온 줄 셋 — ★v1.1)

한 지시서 = 한 일. 이 일은 **재구성**이다: 정답은 그대로 두고 질문 · 힌트 · 해설을 새로 쓴다. 다듬기(`지시서.md`)와 다른 점은 **새 사실을 넣는다**는 것 — 단, 실제로 연 출처가 있는 사실만.

입력: `보낼것/재구성-NN.txt` — 문항마다 `[id] 등급 · 조각 / 질문 / 정답 / 힌트 / 해설 / 까닭`. "까닭"이 왜 재구성인지(기획자 결정 또는 검수 판정)다.

## 1. 무엇을 만드나

- **정답**: 바꾸지 않는다. 정답 범위도 넓히거나 좁히지 않는다.
- **질문**: 진행자 말투(`지시서.md` §2~§5 규칙 그대로 — 끝은 "~일까요?" · 한 문장 기본 · 75자 넘으면 풀어 쓰기 · 첫 문장을 '이 X는'으로 열지 않기 · 언어 한정어 보존). 여기에 **정답과 바로 이어지는 사실 하나**(기획자 말로 "잡지식 하나")를 넣는다.
- **힌트**: 한 줄. 정답의 핵심을 꿰뚫는다 — 아는 사람은 힌트만 보고도 답이 떠올라야 한다(docs/15 §4-1 H9 · H13). 금지 둘: 정답 글자 · 변형 · 번역 조각(H2) · 같은 대상의 다른 이름(우리말 · 원어 · 옛 이름 · 약칭 — H10). 질문에 쓴 사실을 되풀이하지 않는다.
- **해설**: 정답 공개 뒤 읽는 한두 문장. 힌트와 **다른** 사실(둘째 줄). 질문 · 힌트의 되풀이가 아니다.
- **출처**: 질문 · 힌트 · 해설에 들어간 **중요한 사실마다** 실제로 연 페이지 URL. 못 열었거나 기억뿐이면 그 사실은 쓰지 않는다.

## 2. "쉬운 한 줄" 14 는 이렇게

기획자 결정(2026-11-12): *"문제에 스토리가 너무 없다. 맞히면서 잡지식 하나는 알아가면 좋겠다. 쉬운 답일수록 잡지식 하나씩."*

- 답은 **여전히 쉽게** 맞혀야 한다. 원래 관계('스페인의 수도')를 숨기지 않는다 — 잡지식을 **앞에** 얹고 원래 관계로 묻는다.
- 잡지식은 정답과 직접 이어지는 것 하나. 둘 이상 넣지 않는다(힌트 · 해설 몫).
- 잡지식이 정답 아닌 다른 답도 가리키면 안 된다(유일성). 가리킨다면 다른 사실로.

본보기(모양만 — 사실은 출처로 다시 확인해 쓴다):

- 고치기 전: `스페인의 수도는?` (정답 마드리드)
- 고친 뒤: `이베리아반도 한가운데 해발 650m 가 넘는 고원에 자리해, 유럽 수도 가운데 높은 축에 드는 스페인의 수도는 어디일까요?`
- 힌트: `프라도 미술관과 레알 마드리드의 홈구장이 있는 도시.` — 해설: `시내 중심 '푸에르타 델 솔' 광장에는 스페인 도로 거리의 기준점(0km 표지)이 있습니다.`

- 고치기 전: `물의 화학식은?` (정답 H2O)
- 고친 뒤: `수소 원자 둘이 산소 원자 하나에 약 104.5도로 꺾여 붙어 있어 분자가 'ㅅ' 자 꼴인 물의 화학식은 무엇일까요?`

## 3. 그 밖의 재구성(까닭 = clues 나열 · context · type · fact)은 이렇게

★v1.1 재구성-02 부터는 까닭이 갈래 이름으로 온다 — `clues`(이름 · 연도 나열뿐) · `context`(대상이 질문에 없음) · `type`(묻는 것과 정답의 종류가 어긋남) · `fact`(원문 사실이 틀림 — 까닭 줄에 검수가 확인한 내용이 있다. 그 내용도 **네가 출처를 다시 열어** 확인하고 쓴다). 방법은 아래와 같다.

재구성-01 의 까닭은 "나열뿐" · "누가 썼는지 없음" · "어느 나라 · 몇 km 없음" · "넷 나열 뒤 개수" · "정답 범위가 서지 않음" 이다. 그 구멍을 **메우는 사실 하나**를 출처로 찾아 넣고, 나열은 사연 하나로 바꾼다. 힌트 · 해설에 있던 좋은 재료는 질문으로 올려도 된다(그러면 힌트 · 해설을 새로 쓴다).

- 고치기 전(#3992 우신예찬): `친구 토머스 모어의 집에 머물며 쓴 책이 있다고 전합니다. 제목 속 라틴어 낱말이 모어의 성과 말장난이 되도록 지었습니다. 이 책은?` — 까닭: 누가 썼는지 없음.
- 고친 뒤(모양): `네덜란드의 인문학자 에라스뮈스가 친구 토머스 모어의 집에 머물며 썼다고 전하는 풍자서입니다. 제목의 라틴어 낱말이 모어의 성과 말장난이 되게 지었는데요. 이 책은 무엇일까요?`

## 4. 출력 — `받은것/재구성-NN.json`

```json
{
  "chunk": "rebuild-01",
  "results": [
    {
      "id": 4,
      "answer": "마드리드",
      "status": "ready",
      "question": "완성한 질문",
      "hint": "질문과 겹치지 않는 힌트 한 줄",
      "explanation": "정답 공개 뒤 읽을 해설",
      "claims": [
        { "text": "확인한 핵심 사실", "source_url": "실제로 연 페이지 URL", "basis": "web" }
      ],
      "note": "원문에서 바꾼 핵심과 남은 쟁점(없으면 빈 문자열)"
    }
  ]
}
```

- `answer` 는 입력의 정답을 **그대로** 되돌려 적는다(id 어긋남을 기계로 잡기 위해).
- `status`: `ready`(적재 후보) / `no_source`(근거를 못 찾음 — question · hint · explanation 은 null · note 에 무엇을 찾았는지) / `needs_review`(썼지만 쟁점 남음 — note 에 쟁점). `ready` 가 아닌 것은 적재하지 않는다.
- `claims` 는 최종 문항의 중요한 사실마다 하나. `basis` 는 `web` 만 쓴다(기억은 근거가 아니다).
- 입력의 모든 id 를 순서대로 · 누락 · 중복 없이.
- ★v1.1 시간은 **묶음 전체**만 ai-talk 보고에 적는다(문항별 측정은 뺐다 — 015).

★v1.1 V053 에서 나온 줄 셋(재구성-01 · 19 중 고침 2):
- **대상 이름은 질문에 둔다.** ‘어떤 밴드의 노래 · 어떤 드라마의 OST’처럼 대상을 가리키지 않고 곡 · 작품을 물으면 같은 조건의 다른 답이 생긴다(#5463 — 밴드 이름 없이 ‘쾌걸춘향 OST로 인기를 얻은 노래’ → 블라인드가 다른 곡을 댔다). 고친 꼴: `드라마 '쾌걸춘향' OST로 인기를 얻은 뒤 록밴드 이지(izi)의 데뷔 음반에도 실린 노래입니다. 이 노래의 제목은 무엇일까요?`
- **사람의 직함 · 소속은 이 문항의 작품에 대한 것인지 출처에서 확인한다.** 다른 작품의 직함이면 쓰지 않는다(#5463 해설 ‘드라마 음악감독이기도 한 신동우’ — 출처의 음악감독은 다른 드라마였다 → `작사와 작곡은 신동우가 맡았습니다.`).
- **힌트에는 정답을 이루는 낱말 하나도 넣지 않는다.** 기계 검사(`scripts/hint-check.mjs`)는 정답 · 변형의 조각(한글 2글자 이상)이 힌트 낱말의 첫머리에 오면 막는다 — 질문에 이미 나온 조각만 예외다(#7089 정답 ‘안전속도 5030’ · 힌트 ‘…속도 낮추기 정책…’ → 막힘. 질문에는 ‘시속’만 있었다). 제출 전에 정답을 띄어쓰기로 쪼갠 낱말이 힌트에 있는지 하나씩 찾아본다.

제출 전: 정답 글자가 질문 · 힌트에 없는지 · 힌트가 다른 이름을 건네지 않는지 · 질문의 잡지식이 정답만 가리키는지 · 출처가 실제로 그 사실을 말하는지 한 번 더.
