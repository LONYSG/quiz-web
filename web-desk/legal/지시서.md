# 광고 · 저작권 · 노래 — 다른 사이트 사례 찾기 — 지시서 (v1 · 2026-11-25)

친구들끼리 하는 한국어 실시간 퀴즈 웹게임 **퀴즈도장**(quizdojang.com · 개인이 혼자 운영 · 회원가입 · 방 안 채팅 · 게임 점수로 얻는 포인트 · 현금 결제 없음)을 정식으로 열기 전에, 운영자가 정해야 할 것이 있다:

- **광고(구글 애드센스)를 달까, 말까.** 달면 수익이 생기지만, 게임 등급분류 면제 · 사업자등록 · 광고 배치 규칙 같은 짐이 늘어난다.
- 지금 친구 전용 자리에만 둔 두 가지를 어떻게 할까:
  - **캐릭터 이모티콘**(일본 캐릭터 "치이카와" 움직이는 그림 — 운영자가 직접 넣은 것 · 게임 포인트로 뽑는다)
  - **노래 퀴즈**(애플 아이튠즈 미리듣기 30초를 틀고 제목을 맞힌다 — 애플 조건에 "store content 홍보에만 · 오락 용도로 쓰지 말 것"이 있다)

이 일은 **결정을 내리는 것이 아니라, 결정에 쓸 사실과 사례를 문서와 함께 모아 오는 것**이다. 조각마다 질문 몇 개가 있다.

## 1. 찾는 법

- **직접 연 문서만** 적는다. 검색 결과 미리보기만 보고 적지 않는다. 안 열리는 문서는 `unopened` 에 주소만.
- 쓰는 문서: 법령 원문(law.go.kr) · 정부 · 공공기관 안내(한국저작권위원회 · 문화체육관광부 · 게임물관리위원회 · 국세청) · 판결문 · 회사의 공식 약관 · 개발자 문서 · 신문 · 방송 기사 · 법률 사무소 · 학회 글.
- 쓰지 않는 문서: 위키백과 · 나무위키 · 블로그 · 카페 · 지식인 · AI 요약 글(어디를 찾을지 알아내는 데만 쓰고, 거기 달린 원 문서를 연다).
- 사이트 사례는 **그 사이트를 직접 열어** 본 것(약관 · 개인정보 처리방침 · 신고 창구 · 광고가 보이는 자리 · 사업자 정보 · 콘텐츠를 누가 올리는지)과, 그 사이트에 대한 기사를 적는다.
- 문서끼리 말이 다르면 둘 다 적고 `conflict` 에.
- **판단은 짧게, 사실은 넉넉히.** "우리 경우에는 이럴 것 같다"는 `ourCase` 칸에 한두 줄로만 — 근거 문서 id 와 함께. 근거 없이 단정하지 않는다("확인 못 함"이 값진 답이다).

## 2. 인용

- `quote` = 그 문서에 **글자 그대로 있는 문장**(한 문장 ~ 세 문장). 줄이거나 다듬거나 번역하지 않는다.
- `text` = 그 인용이 말하는 사실을 우리말 한두 문장으로. 인용에 없는 것을 더하지 않는다.
- 받는 쪽이 문서를 다시 열어 quote 가 정말 있는지 기계로 확인한다.

## 3. 돌려줄 꼴 — JSON 하나만 (코드 블록 · 설명 글 없이)

```json
{
  "chunk": "01",
  "answers": [
    {
      "q": "조각에 적힌 질문 번호(예: 1-1)",
      "short": "그 질문의 답을 두세 문장으로(문서가 말하는 만큼만)",
      "facts": [
        {"id": "1-1-a", "text": "우리말 사실 한두 문장", "site": "기관 · 매체 · 사이트", "title": "문서 제목", "date": "문서 날짜(없으면 빈 문자열)", "url": "연 주소", "quote": "문서에 있는 문장 그대로"}
      ],
      "cases": [
        {"site": "사례 사이트 이름 · 주소", "what": "그 사이트가 어떻게 하는지 한두 줄", "facts": ["위 facts 의 id"]}
      ],
      "ourCase": "퀴즈도장에 비추면 — 한두 줄 · 근거 id",
      "conflict": [{"about": "무엇이 다른가", "a": "(id)", "b": "(id)"}],
      "unknown": ["찾았지만 확인 못 한 것"],
      "unopened": ["열지 못한 주소"]
    }
  ]
}
```

- 한 번에 다 못 하면 끝낸 질문까지만 온전한 JSON 으로 주고 마지막에 "남은 질문: …" 한 줄.
