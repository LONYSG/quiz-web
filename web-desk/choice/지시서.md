# 객관식 오답 보기 만들기 — 지시서

당신은 한국어 퀴즈 게임의 **객관식 보기**를 만드는 일을 맡았습니다. 함께 올라온 `조각-NN.txt` 에는 문항이 한 줄에 하나씩 약 80개 들어 있습니다.

```
번호 | 분야 | 문제 | 정답
```

게임은 "객관식 10연속" — 문제와 보기 넷(정답 1 + 오답 3)을 보여 주고 7초 안에 고르게 합니다. 플레이어는 20~40대 한국인 친구들입니다. 문항마다 **오답 보기 3개**를 만들어 주세요.

## 1. 좋은 오답 보기

1. **확실히 틀려야 한다.** 그 문제의 답으로도 볼 수 있는 것 · 정답의 다른 이름 · 정답을 포함하는 상위 개념 · 논쟁이 있는 것은 안 됩니다. 조금이라도 "이것도 맞지 않나?" 싶으면 쓰지 않습니다.
2. **정답과 같은 종류여야 한다.** 정답이 사람이면 사람, 나라면 나라, 연도면 연도, 화학 원소면 원소. 문제를 읽은 사람이 보기 넷을 모두 "답일 수도 있겠다" 고 느껴야 합니다.
3. **문제를 안 읽고 보기만 보고 고를 수 없어야 한다.** 정답만 길이 · 말투 · 언어 · 형식이 튀면 안 됩니다.
   - 길이: 오답은 정답 글자 수의 대략 절반~두 배 안.
   - 형식: 정답이 "1950년" 이면 오답도 "○○○○년", 정답이 한글이면 한글, 정답에 단위가 있으면 같은 단위.
   - 숫자 정답은 가까운 숫자로(1950년 → 1945년 · 1953년 · 1961년처럼 그럴듯한 다른 해). 간격을 일정하게 하지 않습니다.
4. **실제로 있는 것이어야 한다.** 지어낸 이름 · 없는 작품 · 없는 용어를 쓰지 않습니다.
5. **너무 뻔한 오답도, 장난 오답도 안 된다.** 세 개 가운데 적어도 둘은 아는 사람도 잠깐 망설일 만한 것으로. 다만 정답보다 훨씬 낯선 전문어를 오답으로 쓰지는 않습니다(정답만 익숙해서 드러남).
6. 세 오답은 서로 다르고, 서로 같은 말의 다른 표기도 아닙니다.
7. 문제 글에 이미 나온 낱말을 오답으로 쓰지 않습니다(문제가 "A 가 아닌" 이라고 지운 것 포함).
8. 보기 하나는 30자 이내.

## 2. 만들 수 없는 문항

아래면 억지로 만들지 말고 `skip` 으로 표시합니다.
- 정답이 문장 · 설명이라 같은 꼴의 오답을 만들면 어색한 문항
- 정답이 여러 개를 나열한 꼴("A와 B")
- 그럴듯한 틀린 답이 사실상 없는 문항(정답 종류가 둘뿐인 경우 등)
- 문제 글만으로는 정답이 하나로 정해지지 않아 보이는 문항 → `skip` + 사유에 "문제 의심"

## 3. 출력 — 이 형식 그대로

**JSON 하나만**(설명 글 없이 · 코드 블록 하나).

```json
{
  "chunk": "01",
  "results": [
    {"id": 1970, "d": ["알 포르노", "소프리토", "몰토 코토"]},
    {"id": 4612, "d": ["타이탄 아룸", "빅토리아 수련", "네펜테스"]},
    {"id": 5329, "skip": "정답이 문장 꼴"}
  ]
}
```

(나쁜 예: 정답이 "알 덴테" 인데 오답에 "알 단테" — 정답의 다른 표기라 쓰면 안 됩니다.)

규칙:
- 조각 파일의 **모든 문항이 한 번씩, 파일 순서대로**. `id` 는 줄 맨 앞 번호 그대로(숫자).
- `d` 는 정확히 3개 · 정답을 넣지 않습니다.
- 문항마다 따로 생각합니다 — 앞 문항의 보기를 돌려쓰지 않습니다.
- 사실이 확실하지 않으면 그 오답을 쓰지 말고 확실한 것으로 바꿉니다.
- 다 쓴 뒤 스스로 확인: 결과 수 = 조각 첫 줄의 문항 수.
