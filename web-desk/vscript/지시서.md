# 지시서 — 영상 대본 초안 (v1 · 2026-11-19)

영상 "오늘의 상식" 2~4회의 대본 초안을 쓴다. 재료는 web 계정이 찾아 둔 것(`보낼것/대본-NN.json`)이다. **검색하지 않는다 · 재료(`sources[].says` · `story` · 그 문항의 question · hint · explanation)에 없는 사실을 더하지 않는다.** 이 초안은 찬종이 읽고 고친 뒤, 사실 확인을 한 번 더 거쳐 목소리로 읽힌다.

## 무엇이 좋은 대본인가 (찬종의 말)

- "아는 문제더라도 몰랐던 사실" — 쉬운 문제라도 **해설에서 새로 얻는 이야기**가 있어야 볼 가치가 있다.
- 힌트가 궁금증을 열었으면 **해설이 갚는다.** (찬종의 예: 힌트가 "일본의 한 자동차 회사가 이 이름을 따 로고에 별 여섯 개를 넣었다"라고 했으면, 해설은 그 회사가 어디인지 말해야 한다.)
- 매일 가볍게 보는 영상이다(★ 2026-11-20 찬종: "아침"이라는 말은 쓰지 않는다 — 여는 말 · 닫는 말에도). 똑똑함을 뽐내는 말투가 아니라 **진행자가 들려주는 말투**("~일까요?" · "~입니다").
- 옛이야기 · 일화는 단정하지 않는다: "~라고 전해집니다" · "~라는 이야기가 있습니다". 재료가 확인한 만큼만 말한다.

## 한 문제에 쓰는 것

| 칸 | 규칙 |
|---|---|
| `question` | 한 문장 · 그 정답이 무엇으로 유명한지(대표 사실)를 묻는다 · "~는, ~은" 꼴(꾸밈 + 쉼표 + 또 꾸밈) 금지 · 정답 낱말이 드러나지 않게 |
| `hint` | 한 문장 · 질문과 겹치지 않는 사실 · 해설의 이야기를 미리 다 말하지 않는다(문만 연다) |
| `explanation` | 주인공은 정답 · 이야기 하나를 **처음 · 가운데 · 끝까지**(누가 · 무슨 일 · 그 뒤 어떻게 됐나 · 그래서) · ★ 길이 한도 없음(2026-11-21 찬종: "너무 간추리려 하기보다 할 만한 설명은 자연스럽게 다" — 앞 판의 "2~4문장 · 120~170자"는 없앴다) |
| `answerLine` | `정답은 ○○!` |
| `say` | `question` · `hint` · `answer` · `explanation` 을 **소리 내어 읽을 글**로: 숫자는 한글로(2013년 → 이천십삼 년 · 1,710개 → 천칠백십 개) · 영어 낱말은 원어 그대로 · 쉼표는 읽을 때 자연스러운 곳에만 · 말투 지시말([밝게] 등)은 넣지 않는다 · 화면 글과 **뜻이 같아야 한다** |
| `topic` | 한 낱말(화면에 뜨는 주제 — "인터넷" · "건축"처럼. 정답을 짐작하게 하는 좁은 말은 안 된다) |
| `note` | 재료를 고친 까닭 한 줄 · 재료만으로 이야기가 모자라면 `"재료 부족"` 이라고만 적고 지어내지 않는다 |

재료의 문장이 이미 좋으면 **그대로 둔다**(`note: "그대로"`). 고치는 것은 위 규칙에 어긋날 때와, 소리 내어 읽었을 때 걸리는 곳뿐이다.

## 본보기 (1회에 실제로 쓴 것 — 꼴을 본다)

```json
{
 "no": 2, "answer": "셀피", "topic": "인터넷",
 "question": "팔을 뻗거나 촬영봉을 써서 자기 모습을 직접 찍은 사진을 가리키며, 옥스퍼드 사전이 2013년 올해의 단어로 뽑은 영단어는 무엇일까요?",
 "hint": "알려진 첫 기록은 2002년 호주 인터넷 포럼에 올라온 글입니다.",
 "explanation": "글쓴이는 술에 취해 넘어져 입술을 다쳤고, 그 상처 사진을 올리며 이렇게 썼습니다. \"초점이 흐려서 미안해요. 셀피라서요.\" 정작 본인은 자기가 만든 말이 아니라고 했습니다.",
 "answerLine": "정답은 셀피!",
 "say": {
  "question": "팔을 뻗거나 촬영봉을 써서 자기 모습을 직접 찍은 사진을 가리키며, 옥스퍼드 사전이 이천십삼 년 올해의 단어로 뽑은 영단어는 무엇일까요?",
  "hint": "알려진 첫 기록은 이천이 년 호주 인터넷 포럼에 올라온 글입니다.",
  "answer": "정답은 셀피!",
  "explanation": "글쓴이는 술에 취해 넘어져 입술을 다쳤고, 그 상처 사진을 올리며 이렇게 썼습니다. \"초점이 흐려서 미안해요. 셀피라서요.\" 정작 본인은 자기가 만든 말이 아니라고 했습니다."
 },
 "note": "그대로"
}
```

힌트가 문을 열고(2002년 호주 포럼 글) 해설이 갚는다(그 글에 무엇이 적혀 있었나).

## 여는 말 · 닫는 말 (편마다 하나씩)

- `opening`: 7~9초 · 오늘의 주제 다섯을 차례로 부른다. 예: "오늘의 상식, 건축, 인터넷, 육상, 고사성어, 우주. 다섯 문제 시작합니다!" (날짜 · 회차 번호 · 채널 이름은 넣지 않는다)
- `closing`: 고정 — "다섯 문제 중 몇 개나 맞히셨나요? 댓글로 알려 주세요. 그럼 내일도 새로운 상식으로 만나요!"
- 둘 다 `say` 도 함께.

## 내는 꼴

`web-desk/vscript/받은것/대본-NN.json` — 다 쓴 뒤 한 번에 저장 · 맨 위에 `"done": true`.

```json
{ "done": true, "bundle": "대본-02", "episode": 2,
  "opening": { "text": "…", "say": "…" },
  "questions": [ { "no": 1, "answer": "…", "topic": "…", "question": "…", "hint": "…", "explanation": "…", "answerLine": "…", "say": { "question": "…", "hint": "…", "answer": "…", "explanation": "…" }, "note": "…" } ],
  "closing": { "text": "…", "say": "…" } }
```

`draw` · `sources` 는 옮겨 적지 않는다(입력 파일에 그대로 있다).

## ★★ 해설 쓰는 법 — 찬종 2026-11-20(대본 2~4회를 읽고 · "다른 해설들과 앞으로 쓸 해설들에도 다 적용되는 말이니까 기억해")

1. **이야기를 끝까지 한다.** "궁금한 이야기라고 해 놓고 더 궁금하게만 해 놓고 어떻게 결론이 났는지를 잘 안 알려 줘." 해설이 연 궁금증은 해설 안에서 닫는다.
   - 나쁨(모나리자): `…그림이 2년 동안 자취를 감추고 여러 나라 신문이 이 사건을 다루면서 모나리자는 오히려 더 유명해졌습니다.` → 그래서 그림은 어떻게 됐나?
   - 나쁨(신호등): `…경찰관이 크게 다치면서 신호등은 철거됐습니다.` → "그럼 지금까지 신호등을 써 온 건 뭐야?"
   - 고치는 법: 마지막 문장을 **결말**(되찾았다 · 다시 나타났다 · 지금은 이렇다)로 쓴다. 재료에 결말이 없으면 지어내지 말고 `"note": "결말 재료 없음"` — 설계가 재료를 더한다.
2. **이야기처럼 쓴다 — 보고서처럼 쓰지 않는다.** "~습니다. ~습니다. 라고 중간에 연결어도 없이 똑같은 말투 반복하면 이상하다 · 좀 더 흥미진진한 스토리처럼 · 너무 딱딱하게 정보 전달하는 느낌."
   - 나쁨(로제타석): `1799년 프랑스군이 … 발견했습니다. 1801년 프랑스가 영국에 항복하면서 돌은 영국으로 넘어갔습니다. 그로부터 20여 년 뒤 … 발표했습니다.`
   - 문장을 **잇는 말**(그런데 · 하지만 · 그러다 · 결국 · 덕분에 · 알고 보니)과 **끝맺음을 바꿔 가며**(~했죠 · ~였는데요 · ~한 겁니다 · ~습니다) 쓴다. 세 문장이 모두 "~습니다."로 끝나면 다시 쓴다. 연도를 문장 머리에 줄줄이 세우지 않는다(꼭 필요한 해 하나만).
   - 이야기에는 **굴곡**이 있다: 무슨 일이 있었나 → 그런데 뜻밖에 → 그래서 결국.
3. **"~라고 전해집니다"를 남발하지 않는다.** "무작정 전해집니다를 남발하는 느낌 · 좀 더 자연스럽게." 전해지는 이야기라는 표시는 **이야기 머리에 한 번**(`…라는 이야기가 유명합니다` · `이런 일화가 전해집니다`) 하고, 그 뒤 문장은 이야기 속으로 들어가 평서문으로 쓴다. 한 해설에 "전해집니다 · ~라고 합니다"가 두 번 넘게 나오면 다시 쓴다.
4. **힌트는 한 번 듣고 바로 알아들어야 한다.** "힌트 잘 이해가 안 가 · 뭔 말인지 모르겠어"(스타벅스 · 마그네트론). 힌트에 "~였다고 전해지는 ~도 나옵니다" 같은 꼬인 문장을 쓰지 않는다. 힌트는 **정답 쪽으로 한 걸음 다가가는 쉬운 사실 하나**다.
5. **질문에 정답을 거의 다 알려 주는 낱말을 넣지 않는다**(도루묵의 '말짱'). 그런 낱말은 힌트로 보낸다.
6. 해설을 다 쓴 뒤 **소리 내어 읽듯** 한 번 읽는다: 내용이 한 번에 들어오는가("포스트잇 해설 뭔가 내용이 안 들어와").
7. (gpt 062 의 제안 · 받음) 해설을 쓰기 전에 **첫 문장이 만드는 궁금증 한 줄 · 마지막 문장이 주는 답 한 줄**을 먼저 적는다. 답이 재료에 없으면 쓰기 전에 `note: "결말 재료 없음"`.
