## 규칙

1. **파일 하나 = 발언 하나.** 이름은 `NNN-누구-주제.md`(예: `002-gpt-답.md`). 번호는 이어서 붙인다. 남의 파일은 고치지 않는다 — 반박 · 보충은 새 파일로.
2. 발언 맨 위에 세 줄: `읽은 것`(직접 연 파일) · `확인 못 한 것` · `한 줄 요약`. 저장소에서 확인한 사실과 추측을 구분해 쓴다.
3. ★ **찬종이 직접 확인할 것(문항 목록 · 고를 것)은 발언 파일에 흩어 쓰지 않고 저장소 맨 위 `찬종-확인.md` 한 곳에 쓴다**(찬종 2026-11-12 — "헷갈리게 써 놨다"). 거기서는 문장마다 **고치기 전 문장인지 고친 문장인지**를 밝히고, 답하는 법을 적는다. 발언 파일의 "찬종에게" 에는 "찬종-확인.md N번" 이라고만 가리킨다.
   찬종이 읽는다. **쉬운 말 · 짧게 · 결정이 필요한 것은 맨 아래 "찬종에게" 에 선택지로.**
4. (002 에서 합의) 새 발언과 필요한 근거만 읽는다 · 합의한 것은 되풀이하지 않고 이견 · 새 근거 · 바뀐 제안만 쓴다 · 끝에 "상대가 답할 것" 또는 "합의 완료 · 찬종 결정 필요" 를 적는다 · 같은 주제는 2~3번 오간 뒤 정리한다.
5. ★ **토론 규칙 (찬종 2026-11-12)**: 상대 의견을 그냥 받아 주지 않는다. **객관적으로 더 낫다고 보는 쪽을 논리와 근거로 강하게 주장한다** — 근거는 저장소에서 확인한 사실 · 실측 숫자 · 찬종이 실제로 고른 것. 반박할 근거가 없을 때만 받는다("예의상 동의" 금지 · 받을 때도 무엇 때문에 설득됐는지 한 줄). **근거로 이긴 쪽 안으로 간다.** 웬만한 것은 둘이 정하고, **끝까지 맞서는 것 · 정말 찬종의 결정이 필요한 것(취향 · 돈 · 사용량 · 되돌리기 어려운 일)만** 맨 아래 "찬종에게" 에 양쪽 주장과 근거를 나란히 적어 묻는다.
6. 의논 중에는 **이 폴더 밖을 고치지 않는다**(코드 · 문서 · DB · 데이터 파일 · git 커밋 모두). 읽기 · 검색 · 읽기 전용 명령만. 합의된 일은 찬종이 "진행" 이라고 한 뒤에 한다.
7. 합의가 되면 max(설계)가 `합의.md` 에 한 장으로 정리하고(★ 2026-11-12 밤 — 역할표 확정 · `합의.md` 있음), 그 뒤 실제 문서(docs/16 등)에 반영한다.
